## 怎么跑

用 Godot 4 打开这个文件夹，按 **F5**。

**画面布局**（视口 700×400）

```
┌──────────────┬──────────────────┐
│ 左侧常驻面板  │   战斗画面        │
│    300 × 400 │    400 × 400      │
│              │    （正方形）      │
│ 血条/蓝条     │                   │
│ DPS/敌人数    │  ★ 这是一个真正的  │
│ 增益          │    SubViewport ★  │
│ 背包网格 8×7  │                   │
│ 宝石详情      │                   │
│ 操作提示      │                   │
└──────────────┴──────────────────┘
```

战斗画面用 `SubViewport` 真正裁成方的，不是"拿面板盖住左半边" ——
所以怪物和投射物**不可能**跑到面板上面去，摄像机的边界也天然是方的。

> 摄像机 `zoom = 2`（`player.tscn`），所以这 400×400 的画面里看到的是 **200×200** 的世界；
> 场地是 400×400，摄像机会跟着玩家滚。想一眼看全整张场地，
> 要么把 `GameWorld.ARENA` 改成 `(100, 100)`，要么把相机 `zoom` 改成 1。

**操作**

| 按键 | 作用 |
|---|---|
| `WASD` / 方向键 | 移动 |
| 鼠标左键 / `空格` | 朝鼠标方向施法（鼠标移到左边面板上时不会走火） |
| `Q` | 在背包里**镶着技能宝石的法杖**之间循环（几根法杖 = 几个技能） |
| `Tab` | 打开伤害计算详情面板（实时的四段式分解 + DPS + 投射物参数） |
| `` ` `` / `F1` | ★ 调试控制台 ★：把图鉴里任何东西生成进背包，可按 技能宝石/辅助/触媒/装备 筛选 |
| `R` | ★ 重开一整局 ★（局模式下放弃当前局、换新种子从第 1 层开始；沙盒下只是重载场景） |

**背包是「背包乱斗」那种网格**（8 × 7 格）

```
      ┌──┬──┬──┬──┬──┬──┬──┬──┐
      │杖◈│◀多│  │杖'│  │戒│头│头│   杖=橡木法杖1×3（◈槽里镶着电球术）
      ├──┼──┼──┼──┼──┼──┼──┼──┤   杖'=见习法杖1×2（镶着火球术）
      │杖│◀闪│  │杖'│  │  │头│头│
      ├──┼──┼──┼──┼──┼──┼──┼──┤
      │杖│◀久│  │  │  │  │靴│靴│   三颗辅助的箭头各指着法杖的一格
      ├──┼──┼──┼──┼──┼──┼──┼──┤
      │  │  │  │  │  │  │靴│靴│
      ├──┼──┼──┼──┼──┼──┼──┼──┤
      │弧│寒│冰│  │  │  │  │  │   还没镶进法杖的技能宝石（库存）
      ├──┼──┼──┼──┼──┼──┼──┼──┤
      │穿│叉│弹│反│速│暴│霜│  │   还没连上的辅助（灰箭头）
      └──┴──┴──┴──┴──┴──┴──┴──┘
```

- ★ **法杖是技能的载体** ★：每根法杖带 1 个镶嵌槽，
  **技能宝石镶进法杖才能施放** —— 裸放在网格里的技能宝石只是库存
- ★ **箭头指着法杖的哪一格都算连上**，辅助的是槽里的技能 ★
- **法杖越长，周身的箭头位越多**（1×2 有 6 个、1×3 有 8 个）——
  换一根更长的法杖，本身就是"连线面积"的升级
- 多根法杖 = 多个能同时携带的技能，`Q` 在它们之间循环
- ★ **触媒**（紫色的特殊辅助）★：箭头指着法杖时，**条件达成就自动触发**槽里的技能——
  无施法动作、正常扣蓝、蓝不够不触发。共 6 颗：施加感电 3 次 / 点燃 3 次 /
  冰缓 1 次 / 击中 5 次 / 移动 20 格 / 每 5 秒。副法杖挂触媒 = 自动副攻
- 箭头颜色：**绿** = 连上了　**红** = 指着法杖但槽里技能的标签不匹配
  **灰** = 没指着法杖，或法杖的槽还空着

**操作**

- 左键点一颗宝石 → 拿起来（连它的朝向一起；拿法杖时槽里的宝石跟着走）
- 手上有东西时左键点格子 → 放下（半透明预览：绿=放得下，红=放不下）
- ★ **手上是技能宝石、点一根法杖 → 镶进槽位**（预览是青蓝色）★
  槽里是同款 = 合成升级；槽里是别的 = 交换（旧的回到手上）
- ★ **空手右键点法杖 → 把槽里的宝石取出来拿在手上** ★
  （详情面板的「取出宝石」按钮是备用入口）
- ★ **右键 → 把手上的宝石转 90°** ★，箭头跟着转，预览里直接能看到会指到哪
- 鼠标**停**在任何宝石上 → 下方显示它的完整属性；`[-]` `[+]` 升 / 降级
- **丢弃**：把东西拿在手上 → 点两次「丢弃」按钮（第一次是确认提示，防误触）。
  丢法杖时槽里的宝石会一起丢掉，提示里会写明
- **重置背包** → 恢复出厂摆法（摆乱了的后路）

**★ 背包会记住 ★**

摆法、朝向、宝石等级、当前用哪个技能，全都存在
`%APPDATA%\Godot\app_userdata\PoE-like ARPG\backpack.json` 里。
按 `R` 重开、关掉游戏重进，背包都是你上次摆的样子。

存的是 **JSON**，可以直接打开看、手改、出问题时一眼知道哪不对。
读档做了三层容错，因为你还在改宝石表、存档一定会和代码对不上：

| 情况 | 怎么处理 |
|---|---|
| 存档里有已经删掉的宝石 | 跳过它，其余照常还原（不让整个存档作废） |
| 位置冲突 / 越界（网格改小了、形状改大了） | 别把宝石弄丢，自动找个空地放 |
| 图鉴里新加了宝石，老存档里没有 | 自动补进空地（`GemSave.fill_missing`） |
| 文件坏了 / 版本号对不上 | 退回默认摆法，不炸 |

★ 存的是「当前技能是**哪颗宝石**」而不是下标 ★ ——
`skill_index` 是 `skill_items()` 里的位置，而那个列表按摆放位置排序，
挪一下宝石就指到别人身上去了。

## 敌人：分波上场 + 精英怪

一个战斗房的怪比以前多得多（第 1 层第 1 步 4 只 → 第 4 层第 6 步 16 只），但**不是一口气全放**：
同一时刻场上最多 4~8 只，死一只隔 0.9 秒补一只，直到名单放空、全部打死才算清房。
Boss 房不分波：Boss 带 2~5 只护卫一起上。

**精英怪**（金色、体型更大、头顶写着词条名）从第 1 层第 4 步开始出现，排在每房的**最后**上场。
它比同房普通怪硬得多（+80% 生命 / +30% 伤害），身上还挂 1~2 条**随机词条**：

| 词条 | 效果 | 怎么对付 |
|---|---|---|
| 迅捷 / 狂暴 / 暴虐 | 追得快 / 砍得勤 / 砍得疼 | 先杀它 |
| 坚韧 / 巨型 / 石肤 | 血更厚 / 血翻倍但走得慢 / 承伤 −25% | 石肤能被感电抵消（同一乘区相加） |
| 抗火 / 抗冰 / 抗电 | 对应抗性 +30~35% | 换一系技能，或靠感电放大 |
| 灼热之爪 / 霜爪 / 雷爪 | 挨一下：着火 / 冰缓 / 感电 | 别站着挨打 |

词条是按局种子抽的：读档重打还是那几只，刷不了"好打的词条"。词条池在 `data/monster_affixes.gd`，
加一条词条 = 加一个函数，一行战斗逻辑都不用写。

## 装备系统

装备和宝石住在**同一张网格**里，规则只有一条：

> ★ **放在背包里就生效，不需要连箭头** ★

| 装备 | 占地 | 加成 |
|---|---|---|
| 见习法杖 | 1×2 | ★ 没有词缀，1 个镶嵌槽 ★ —— 开局那根，价值就是能装技能 |
| 橡木法杖 | 1×3 | 1 个镶嵌槽 + 更多 30% 法术伤害，提高 25% 施法速度 |
| 铁头盔 | 2×2 | 增加 200 生命上限，增加 150 护甲 |
| 旅者之靴 | 2×2 | 提高 20% 移动速度 |
| 烈焰戒指 | 1×1 | 增加 15 点火焰伤害，提高 120% 火焰伤害 |
| 秘法腰带 | 3×1 | 魔力回复 +8/秒，增加 60 魔力上限 —— 连一堆辅助后蓝不够用，靠它续 |
| 蓝玉护符 | 1×1 | 提高 50% 魔力回复（和腰带的 +8 是不同乘区，相乘生效） |

> 法杖是唯一带镶嵌槽的装备（`socket_count = 1`），而且
> ★ **法杖的词缀只对槽里镶着的技能生效** ★ ——
> 橡木法杖的 30% 法术伤害不会加给别根法杖里的技能，换法杖 = 换这个技能的增幅包。
> 其它装备的规则不变：放在背包里就全局生效，不需要连箭头。

**★ 这就是网格背包的核心取舍 ★**
宝石都只占 1 格，所以"占地方"这件事全压在装备身上：
背包就 8×7 = 56 格，装备摆得越舒服，留给「技能石 + 四面箭头」的空间就越少。
法杖竖着占 3 格很难塞，转 90° 变成横着的 3×1 —— 塞哪、怎么转，就是构筑的一部分。

注意烈焰戒指只加**火焰**伤害：你用电球术（闪电）时它一点用都没有，
但它只占 1 格，所以留着也不亏 —— 这种"要不要为一个技能带专属装备"的取舍才是重点。

**词缀分四层**（`CombatEntity._layers()`，查询时叠在一起算）：

| 层 | 内容 | 谁来维护 |
|---|---|---|
| `gear_mods` | 天赋 / 被动树 | `DemoContent.make_player()`，不随背包变 |
| `equip_mods` | ★ 背包里的装备 ★ | `Player.rebuild()` 按背包整层重建 |
| `skill_mods` | 箭头连着当前法杖的辅助宝石 | `Player.rebuild()` 按箭头整层重建 |
| Buff | 增益 / 减益 | `BuffContainer` |

按 `Tab` 打开的伤害面板会把这四层分开列出来，一眼看清每一条加成的出处。

**跑测试**
```
godot --headless --path . --script res://test/run_tests.gd    # 数值单元测试（271 个断言）
godot --headless --path . --script res://test/smoke_test.gd   # 集成冒烟测试
```
前者测纯数值逻辑，后者真的把游戏跑起来，确认
"放火球 → 掉血 → 上点燃 → DoT 持续掉血 → 弹射 → 分叉 → 电球术撞墙反弹 → 感电
→ **背包里拿起/转方向/放下/箭头连上** → **存盘再读回来**"整条链路是通的。
**改了 combat/ 或 game/ 就各跑一遍。**

> 新加了带 `class_name` 的脚本之后，先跑一次
> `godot --headless --path . --import`，否则测试会报 "Identifier not declared"（全局类名还没注册）。

## ★ 必须理解的两件事

### 1. 四段式公式

```
最终值 = (基础值 + Σ增加点数) × (1 + Σ提高%) × Π(1 + 更多%)
         └─ FLAT ─┘            └─ INCREASED ─┘  └─── MORE ───┘
```

- **INCREASED（提高）** 所有同类**加在一起**算一个乘区 → 两条 +50% = ×2.0
- **MORE（更多）** 每一条**独立连乘** → 两条 +50% = ×2.25

这两个混成一个 `float` 是 PoE-like 项目最常见的返工点。

### 2. 标签系统

每次伤害带一组标签，每条词缀声明它要求哪些标签，`has_all` 匹配。
所以「提高 40% 火焰投射物伤害」是**纯数据**，不需要写任何代码。

派生标签（如「元素」）必须是**独立的一位**，由 `CombatTags.normalize()` 自动补上 ——
不能写成 `FIRE|COLD|LIGHTNING`，否则 `has_all` 会要求三种元素同时成立。

### 3. 投射物：穿透 / 分叉 / 弹射

三者的判定顺序在 PoE 里是**写死的**，不是可配置的：

```
穿透 > 分叉 > 弹射
```

也就是说：只要这一发还有穿透次数，命中时就**绝不会**分叉或弹射。
这也是为什么 PoE 里穿透和分叉/弹射通常不会配在同一套装备上 —— 它们互相压制。

| 行为 | 命中后 | 次数怎么算 |
|---|---|---|
| **穿透** | 方向不变，继续飞 | 固定次数用完后，还能靠「穿透几率」继续穿 |
| **分叉** | 裂成 2 发，各偏 30°，原来那发消失 | 分叉出来的**不能再分叉**，但穿透/弹射/反弹次数继承 |
| **弹射（连锁）** | 转向搜索半径内的下一个敌人 | 优先没打过的；都打过了可以弹回去（PoE 行为，双怪来回弹是弹射流主要伤害） |

三种行为的次数全都走属性系统（`PIERCE_COUNT` / `FORK_COUNT` / `CHAIN_COUNT`），
所以「增加 1 次弹射，仅限火焰技能」是**纯数据**，不用改一行代码。

**★ 撞墙反弹（`BOUNCE_COUNT`）是第四种、也是完全独立的一种 ★**

反弹和上面三种**互不消耗**：撞墙不掉命中次数，命中也不掉反弹次数。
所以电球术可以配成「0 穿透 + 8 反弹」，在小房间里弹到死为止。
另外弹墙 = 掉头回来，所以弹完之后**可以再打一次刚才那个目标**
（`try_bounce()` 会清掉 `last_hit_id`）。

### 4. 技能石系统（★ 电球术是样板 ★）

> **「电球术」= PoE 的 Spark 在中文版里的译名**，就是那个一次射一大把乱窜小球、撞墙会弹的技能。

PoE 的技能不是"角色学会的"，而是**一颗可以拔下来换给别人的石头**。这一层拆成三个类：

| 类 | 是什么 | 在哪 |
|---|---|---|
| `SkillSpec` | 「这一次施法用什么参数」 | `combat/skill_spec.gd` |
| `SkillGem` | 「玩家背包里那颗石头」：等级 + 成长 + 标签 | `combat/skill_gem.gd` |
| `SupportGem` | 「一组带代价的词缀」+ 连接标签要求 | `combat/support_gem.gd` |
| `GemShape` | 宝石占几格、箭头朝哪、怎么旋转 | `combat/gem_shape.gd` |
| `GemGrid` | ★ 背包网格：谁摆在哪、宝石镶进哪根法杖、箭头指着谁 ★ | `combat/gem_grid.gd` |
| `GemLink` | 网格**算出来的结果**：槽里的技能石 + 指着法杖的那些辅助 | `combat/gem_link.gd` |

`SkillGem.build()` = 把「当前等级的宝石」展开成一份 `SkillSpec` 交给战斗管线。
等级、魔力倍率这些只属于宝石的概念，一点都不会漏进伤害公式里。

★ **法杖是技能的载体（ADR-020）** ★ —— 技能宝石镶进法杖的槽才能施放；
辅助连接由 `GemGrid` 每次按摆放位置重算。想改连接，就去背包里挪宝石、转方向：

- 想给一个技能连更多辅助 → 换更长的法杖（1×3 的周身有 8 个箭头位），在它周围腾地方
- 一颗辅助只有一个箭头 → 不可能同时辅助两根法杖
- 想换个技能吃这套辅助 → 把槽里的宝石换掉就行，箭头一根不用动

规则全是几何的、纯逻辑的，所以照样能单测（`_test_gem_grid_arrows` / `_test_wand_socket`）。

**★ 电球术（Spark）—— 标准技能石 ★**：`data/gem_library.gd → gem_spark()`

| 属性 | 1 级 | 说明 |
|---|---|---|
| **Tag** | 闪电, 法术, 投射物, 持续时间 | 决定吃哪些词缀 + 能连哪些辅助 |
| **等级** | 1 / 5 | ★ 每级 +28 点伤、+2 消耗 ★ 只有 5 级，每级都是一大步（≈PoE 的 4~5 级） |
| **消耗** | 6 魔力 | 每连一颗辅助再乘一次倍率 |
| **施放时间** | 0.65 秒 | 出手频率 = 施法速度 ÷ 施放时间 |
| **投射物速度** | 150 | |
| **点伤** | 55 | ★ 这是**单发**的伤害，一次射 4 发 ★ |
| **单次发射数量** | 4 发 | 「多重投射」→ 6 发（扇面不变，排得更密） |
| **投射物持续时间** | 2.4 秒 | 「延长持续」×1.45 → 3.5 秒 |

★ **电球术的伤害 = 单发点伤 × 发数 × 每发活着的时间** ★
所以它的构筑方向和"单发大伤害"的火球术完全相反：

- 「投射物数量」→ 一次射更多发 ← 所以它带 **投射物** 标签
- 「技能持续时间」→ 每发活得更久 → 在房间里弹得更久 → 打到更多次 ← 所以它带 **持续时间** 标签

**标签是怎么限制辅助宝石的**

```gdscript
support_duration().required_tags = T.DURATION
电球术 (…| T.DURATION)  → can_support 通过 ✔
火球术 (没有 DURATION)  → 连不上，界面写明原因 ✘
```

**辅助宝石的词缀只属于箭头指着的那根法杖（槽里的技能）**：走 `CombatEntity.skill_mods`
这一层，切技能时整层换掉。所以指着电球术法杖的「多重投射」，不会让你的火球术也变成多发。

### 5. 电球术的投射物机制

`data/gem_library.gd → gem_spark()`。这个技能存在的意义是把投射物的每条机制都点亮一遍：

| 机制 | 参数 | 效果 |
|---|---|---|
| 散射角 | `spread_mode = FAN`，`spread_arc_deg = 90` | 4 发均分 90° 扇面，两端各 ±45° |
| 随机抖动 | `spread_jitter_deg = 20` | 每发再随机偏 ±20°，**每次施法弹道都不一样** |
| 随机位移 | `spawn_jitter = 5` | 发射点也抖一下，多发不会挤成一条线出生 |
| 飞行乱窜 | `wander_deg = 26` / `wander_interval = 0.09` | 每 0.09 秒转一个 ±26° 的随机角 —— 电球术最标志性的手感 |
| 撞墙反弹 | `base_bounce = 5` | 撞到场地边缘镜面弹回 |
| 分叉 / 连锁 | 技能自带 0 次 | 全靠支援宝石，装上立刻生效 |

数值上是「单发很弱、发数极多」（基础 55 伤害，火球是 200），
所以它吃**投射物数量**和**持续时间**的收益远大于吃单发伤害 —— 这也是 PoE 里电球术的构筑方向。

`FAN` 和 `STEP` 两种散射模式的区别：

```
FAN （总扇面固定）   3 发 → 相邻 30°      5 发 → 相邻 15°   扇面始终 60°
STEP（相邻夹角固定） 3 发 → 扇面 30°      5 发 → 扇面 60°   夹角始终 15°
```

多重投射支援给电球术加 2 发时，是**排得更密**而不是**扇得更宽** —— 这正是 FAN 模式的意义。

**分层**：角度、次数、计时全在 `combat/`（纯数值，`ProjectileSpec` / `ProjectileState`），
"往哪个方向转多少像素""镜面反射怎么算"在 `game/projectile.gd`。
撞墙判定用的是**场地矩形**而不是物理碰撞，因为 `Area2D.body_entered` 不给法线，
拿不到法线就没法算反射；以后换 TileMap 地形时改成 `ShapeCast2D.get_collision_normal()`，
上层 `state.try_bounce()` 一行都不用动。

游戏里按 `1`~`5` 连/拔辅助宝石就能直接对比。辅助宝石本身也只是一组词缀：

```gdscript
support_chain().mods = [
	M.new(S.CHAIN_COUNT, M.Kind.FLAT, 2.0, T.PROJECTILE),
	M.new(S.DAMAGE, M.Kind.MORE, -0.25, T.PROJECTILE),  # 代价
]
```
连上 = `skill_mods.add_all(link.mods())`，拔下 = `skill_mods.remove_by_source(sup.source_key())`。

判定逻辑在 `combat/projectile_state.gd`，同样不依赖任何 Godot 节点，所以能单测。
`game/projectile.gd` 只负责"照着做"：改方向、生成新的、或者消失。

## 分层原则

`combat/` 里**不允许出现 Node、Sprite、位置坐标**。
表现层（`CharacterBody2D`）应该**持有**一个 `CombatEntity`，而不是继承它：

```gdscript
extends CharacterBody2D
var stats := CombatEntity.new(&"player")

func _physics_process(delta: float) -> void:
    DamagePipeline.resolve_dots(stats, delta)   # 推进 Buff 和 DoT
    if not stats.is_alive():
        die()
```

好处：战斗数值能脱离游戏跑测试、能做离线 DPS 计算器、将来联机可以直接搬到服务器验算。

## 项目已配好的关键设置

- **纹理过滤 = Nearest**（不改的话像素图会被糊掉，这是像素游戏第一坑）
- 视口 700×400（= 左侧面板 300 + 战斗画面 400），`canvas_items` 拉伸 + `keep` 宽高比
- 渲染后端 `gl_compatibility`（2D 够用，兼容性最好）

**关于 SubViewport 的两个坑**（改布局时会踩到）：

1. SubViewport 有**自己的一份 `World2D`**，所以场地里的东西（角色、投射物、
   连同 `_setup_walls()` 造的墙）必须全部 `view.add_child()`，
   挂到 `GameWorld` 自己身上的话就和别人不在同一个物理世界里，永远撞不到。
2. 玩家住在 SubViewport 里，**问不到"主窗口的鼠标在哪"**，所以"鼠标在不在战斗区里"
   由 `GameWorld._process` 判断后写进 `Player.can_aim` —— 否则在左边面板点宝石
   会顺手放一发技能。★ 判断时两边必须是**同一个坐标系** ★：
   `get_global_rect()` 配 `get_global_mouse_position()`（都是视口坐标 300~700）。
   写成 `get_rect()`（父坐标）配 `get_local_mouse_position()`（自身坐标 0~400）
   的话，只有最右边 100px 能施法 —— 这个坑踩过一次，冒烟测试里现在有六条断言盯着。

   （顺带：`SubViewport.get_mouse_position()` 是引擎按容器位置**实时推算**的，
   不会过期，所以瞄准方向不用自己修正。）
