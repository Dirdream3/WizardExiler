# 设计决策记录（ADR）

> ★ **改动之前先在这里搜一下** ★
> 这里记的都是**想清楚之后才这么做的**。看着奇怪 ≠ 写错了。
> 如果你（人或 AI）觉得某条决定是错的，**改之前先在 PR 里说明理由**，别默默"顺手修好"。

格式：**背景 → 决定 → 后果**。新决定追加在最后，不要插在中间（减少 diff 冲突）。

## ADR-001 `combat/` 零引擎依赖

**背景**：PoE 式词缀交互复杂，不写测试必炸。但 Godot 的 Node 很难在 headless 下测。

**决定**：`combat/` 里不许出现 `Node` / `Sprite` / `Camera` / 场景坐标 / `FileAccess` / `get_tree()`。
表现层**持有** `CombatEntity`，不是继承它。

**后果**：
- ✅ 271 个单元测试能存在
- ✅ 能做离线 DPS 计算器；将来联机能搬到服务器验算
- ⚠️ 文件读写、找最近的敌人这类事必须由 `game/` 喂进来（`GemGrid.from_data` 收一个 `resolve` 回调而不是直接查图鉴，就是这个原因）

## ADR-002 四段式公式只有一处实现

**背景**：`INCREASED`（提高，相加共用一个乘区）和 `MORE`（更多，各自连乘）如果混成一个 float，
整个装备构筑的深度就没了。这是 PoE-like 项目最常见的返工点。

**决定**：公式只写在 `StatSet.breakdown_layered()` 一处，所有算伤害的地方都走它。

**后果**：任何"我这里简单算一下就行"的想法都要拒绝。有第二处实现，数值一定对不上。

## ADR-003 标签用位掩码，派生标签独立占一位

**背景**：每帧要做成千上万次标签匹配。而且「元素伤害」这种派生标签容易写错。

**决定**：标签是 `int` 位掩码；`ELEMENTAL` **独立占一位**，由 `CombatTags.normalize()` 在查询时自动补上。

**后果**：不能写 `ELEMENTAL = FIRE|COLD|LIGHTNING` ——
匹配用的是 `has_all`（要求全部包含），那样写会变成"必须同时是火+冰+电"，永远吃不到。

## ADR-004 技能石和 SkillSpec 分成两层

**背景**：`SkillSpec` 是"这一次施法用什么参数"，没有等级概念。但玩家手里的是一颗有等级、会成长的石头。

**决定**：`SkillGem`（等级 + 成长曲线 + 标签）通过 `build()` 展开成 `SkillSpec`。

**后果**：等级、辅助宝石的魔力倍率这些只属于宝石的概念，一点都不会漏进伤害公式。
`build()` 每次返回**新的** `SkillSpec`（`SkillSpec.duplicate()`），改返回值不会污染模板。

## ADR-005 「电球术」= PoE 的 Spark

**背景**：AI 把中文「电球」按字面理解成 Ball Lightning，凭空造了一个脉冲技能，返工一整轮。

**决定**：项目采用 **PoE 中文版的官方译名**。
- **电球术** = Spark（一次射 4 发乱窜的小球，撞墙会弹）← 本项目的标准技能石样板
- 闪电球 = Ball Lightning（已删除，见 ADR-011）

**后果**：见 [AGENTS.md 名词对照表](../AGENTS.md#2--名词对照表踩过坑务必先看)。
**拿不准英文原名就问，不要猜。**

## ADR-006 连接关系用「网格 + 箭头」，不用插槽

**背景**：一开始做的是 PoE 那种"技能栏三格，每格 1 主石 + 4 插槽"。
但项目主人想要「背包乱斗」那种网格背包。

**决定**：所有宝石住在同一张 8×7 网格里。辅助宝石带一个**箭头**，
**箭头指进哪颗主动技能石，就辅助哪颗**。`GemLink` 变成网格**算出来的结果**，
没有 `socket()` / `unsocket()`。

**后果**：
- ✅ "怎么摆"本身成了构筑的一部分
- ✅ 一颗辅助只有一个箭头 → 不可能同时辅助两个技能（规则天然自洽）
- ✅ 技能石只占 1 格 → 四面最多 4 个箭头位 → **PoE 的「4 连」是几何自然的结果，不是写死的上限**
- ⚠️ 想改连接只能去背包里挪宝石。**别再加回 socket API**

## ADR-007 战斗画面用 SubViewport 真正裁成正方形

**背景**：要"左边常驻 UI + 右边正方形战斗画面"。
最省事的做法是"拿不透明面板盖住左半边"，但那样怪物会跑到面板"下面"、边界是假的。

**决定**：战斗画面是真正的 `SubViewport`（400×400），场地里的一切都挂在它底下。

**后果**：
- ✅ 硬边界，怪物和投射物不可能跑到面板上面去
- ⚠️ SubViewport 有**自己的 World2D** → 场地里的一切（含墙）必须 `view.add_child()`
- ⚠️ 玩家问不到主窗口的鼠标 → `can_aim` 由 `GameWorld._process` 写进去

## ADR-008 `can_aim` 用几何判断，不用 `gui_get_hovered_control()`

**背景**：需要"鼠标在左边面板上时不施法"。

**决定**：`GameWorld._process` 里 `battle.get_global_rect().has_point(battle.get_global_mouse_position())`，
结果写进 `Player.can_aim`。

**后果**：★ **两边必须是同一个坐标系** ★
- `get_global_rect()` + `get_global_mouse_position()` —— 都是视口坐标（300~700）✅
- `get_rect()` + `get_local_mouse_position()` —— 前者父坐标、后者自身坐标 ❌

这个坑踩过一次（"只有屏幕最右边 100px 能施法"），冒烟测试现在有 6 条边界断言盯着。

## ADR-009 背包存档存 JSON，而且存 id 不存下标

**背景**：加了网格背包之后，"怎么摆"就是构筑本身。不存盘的话每次按 R 重开就全没了。

**决定**：
- 存 **JSON**（可读、可手改、出问题一眼看出哪不对），放 `user://backpack.json`
- 序列化在 `GemGrid.to_data/from_data`（纯逻辑，能单测），文件读写在 `game/gem_save.gd`
- **存「当前技能是哪颗宝石」的 id，不是 `skill_index`**

**后果**：
- `skill_index` 是 `skill_items()` 里的位置，而那个列表**按摆放位置排序** ——
  挪一下宝石、或者补进一颗新技能石，同一个下标就指到别人身上去了
- 读档做了四层容错（删掉的宝石 / 位置冲突 / 新增内容 / 文件损坏），因为宝石表还在改
- 测试必须在场景 `_ready` **之前**设 `GemSave.autosave = false`，否则跑一次测试就覆盖玩家存档

## ADR-010 装备和宝石同网格，放着就生效

**背景**：要加装备系统。可以做成独立的"装备栏"，也可以像背包乱斗那样放进同一张网格。

**决定**：装备住在同一张网格里，**只要在背包里就生效，不需要连箭头**。
宝石都只占 1 格，装备占多格（法杖 1×3、头盔 2×2）。

**后果**：
- ✅ "占地方"的取舍全压在装备身上：背包 56 格，装备摆得越舒服，留给"技能石 + 四面箭头"的空间越少
- ✅ 装备旋转有意义（法杖竖着 1×3 塞不进的地方，转成 3×1 就行）
- 词缀多了一层 `equip_mods`（见 ADR-012）

## ADR-011 删掉脉冲机制和「闪电球」

**背景**：ADR-005 那次误解造出来的 Ball Lightning 用了一套"沿途反复放电"的脉冲机制。
项目主人明确要求删掉。

**决定**：整套删除 —— `with_pulse` / `is_pulsing` / `PULSE_RATE` / `collides_with_enemies` /
`pulse_ticks` / `pulse_dps` / `max_pulses` / `Projectile._do_pulse` / 电场圈的画法 / 闪电球贴图。

**顺带删了**「增大范围」辅助宝石 —— 它唯一的作用是放大脉冲半径，
脉冲没了它就是一颗"装上去什么都不会变"的宝石，留着比删掉更误导人。

**后果**：`AREA_OF_EFFECT` 属性保留（以后做真正的范围技能还要用），但目前无人使用。

## ADR-012 词缀分四层，装备和辅助宝石那两层「整层重建」

**背景**：装备、辅助宝石、天赋的生效范围完全不同，混在一个 `StatSet` 里没法维护。

**决定**：`CombatEntity` 持有四层，查询时叠在一起算一次四段式：

| 层 | 内容 | 维护方式 |
|---|---|---|
| `gear_mods` | 天赋 / 被动树 | 不变 |
| `equip_mods` | 背包里的装备 | `Player.rebuild()` **整层重建** |
| `skill_mods` | 箭头连着当前技能的辅助宝石 | `Player.rebuild()` **整层重建** |
| Buff | 增益 / 减益 | `BuffContainer` 计时 |

**后果**：
- ✅ 背包一变就整层清空重填，不用追"哪一条该删"，也不会串味
  （箭头指着电球术的「多重投射」不会让火球术也变多发）
- ✅ 顺带修掉一个老问题：以前 `make_player()` 里硬写着 source 叫 `staff` / `ring_of_flame` 的词缀，
  但游戏里根本没这两件东西。现在它们是真装备，**id 保持不变**，所以角色总加成一点没变
  （老的伤害测试全部原样通过），但终于有实物了

## ADR-013 施放时间是「秒」，不是「倍率」

**背景**：`SkillSpec.cast_time` 原来注释成"耗时倍率"，含义模糊。

**决定**：它就是 PoE 技能石上印的**基础施放时间（秒）**。

```
每秒出手次数 = 施法速度倍率 ÷ 施放时间
```

**后果**：「提高施法速度」是缩短这个时间，不是改这个字段本身。
`Player._try_cast()` 里 `_cast_cd = skill.cast_time / speed`。

## ADR-014 不写恒真的断言

**背景**：曾经写过一条断言"SubViewport 鼠标 = 主视口鼠标 − 容器左上角"，
实测发现引擎是**按容器位置实时推算**的，这条永远成立。

**决定**：删掉，只留"值确实变了"这条有效的。

**后果**：写断言之前先问自己 —— **它可能红吗？**
恒真的断言比没有更糟，它给假信心。同理，探针脚本自己也要加断言
（曾经因为探针脚本没检查 `place()` 的返回值，把"脚本选错落点"误判成"存档功能坏了"）。

## ADR-015 文档拆成「给人看的」和「给 AI 看的」，但规约只有一份

**背景**：需要支持多人 + 多 AI 协作，同步到 GitHub。

**决定**：
- `AGENTS.md` —— **唯一的 AI 规约**，Cursor / Copilot / Codex 等通用
- `CLAUDE.md` —— 只是个指针，指向 `AGENTS.md`（Claude Code 会自动读它）
- `CONTRIBUTING.md` —— 人类的流程（环境、分支、提交、PR）
- `docs/` —— ARCHITECTURE（怎么组织的）/ DECISIONS（为什么）/ TASKS（在做什么）

**后果**：规约只有一份，不会出现"各家 AI 遵守不同规则"。
加新的 AI 工具时，只要让它读 `AGENTS.md` 就行。

## ADR-016 局内流程放在独立的 `run/` 层，规矩和 `combat/` 相同

**背景**：加入杀戮尖塔式的局结构（7 步地图 → 战斗/商店 → 奖励三选一 → 最终 Boss）。
流程规则（能不能进房、金币够不够、走到第几步）和战斗数值一样容易出细碎 bug，必须能单测。

**决定**：
- 新建 `run/` 目录（`run_map` / `run_state` / `run_rewards`），**零 Godot 场景依赖**，规矩同 `combat/`
- 依赖方向扩成：`game/` → `data/` → `run/` → `combat/`。
  `run/` 不认识图鉴 —— 奖励候选池由调用方传进来，单测时传假对象就能验规则
- ★ 整局由一个种子决定 ★（地图、奖励候选、商店货架全部从种子推出来）。
  存档只存 `种子 + 步数 + 金币 + 背包`，图和货架读档后**重新生成**，天然一致，
  顺便封死"读档刷奖励 / 刷货架"
- 局模式和沙盒模式用 `RunSession.enabled` 切换：局模式开局只有一颗孤石，
  **不走** GemSave（它会把图鉴缺的自动补进背包，和"一切靠打"直接冲突），
  局的背包存进独立的 `run.json`
- 读档一律回到**当前步的选房阶段**：打到一半退游戏 = 这一步重打，简单无歧义

**后果**：局流程 47 条断言进了 `run_tests.gd`；冒烟测试加了第八段
（孤石开局 → 选房 → 清房 → 三选一 → 回地图）。怪物按步数成长、Boss 都只是
"叠了词缀 / 改了基础值的 CombatEntity"，没有为局模式写任何新战斗逻辑。

## ADR-017 图标是 UI 层的 id 映射；冰缓挂移动速度；怪的追击速度入属性系统

**背景**：接入 `assets/icons/` 下的 19 张图标，并把主动技能从 2 颗扩到 5 颗
（电弧 / 寒冰弹 / 冰霜脉冲）+ 冰霜增强辅助。冰系技能需要一个「冰缓」异常状态。

**决定**：
- ★ 图标按 id 找（`assets/icons/<id>.webp`），映射写在 `UIHelper.gem_icon()` ★
  —— 和格子颜色一样是 UI 层的事，`combat/` 和 `data/` 里**不放任何资源路径**。
  加一件新内容只要丢一张同名图进目录；没有图就退回文字短名，不会变成无名色块
- 图标文件统一用 **.webp 真实扩展名**。曾经 19 张图全是 WebP 却顶着 .png 的
  扩展名，Godot 按扩展名选导入器 → 全部导入失败，这就是"图生成了却没接上"的原因。
  冒烟测试现在会逐件检查图标能否真的加载
- 冰缓（chill）挂在**移动速度 -30%** 上，REFRESH 不叠层。不挂攻击速度 ——
  普通怪从没设过 ATTACK_SPEED 基础值（是 0），挂攻速就是一条恒真数据
- 为了让冰缓真的生效，Enemy 的追击速度从写死的 `CHASE_SPEED` 常量改成
  `stats.get_stat(MOVE_SPEED, 0, CHASE_SPEED)` —— 基础值不变，没有词缀时
  行为和原来一模一样，但 Debuff 从此能减速怪
- 三颗新技能各占一条构筑路，不和老技能重叠：
  电弧 = 弹射专精（怪越密越强）；寒冰弹 = 慢速穿透弹幕；
  冰霜脉冲 = 短射程高伤冰锥，**故意不带**【持续时间】标签（射程就是它的代价，
  能被「延长持续」拉长射程它就只是更强的寒冰弹）

**后果**：主动 5 / 辅助 10，全部自动进入局模式的奖励池和商店（`all_actives()` /
`all_supports()` 是唯一入口）。`run_tests.gd` 新增 4 组断言（新技能参数 / 冰缓 /
冰霜增强连接规则 / 价目表），冒烟测试新增图标加载检查。

## ADR-018 同款宝石叠放 = 合成升级，规则住在 GemGrid

**背景**：局模式的奖励和商店会给出重复的宝石，重复的第二颗除了占格子没有任何用处。

**决定**：
- ★ 把手上的宝石叠到一颗**同 id** 的宝石上 = 合成：手上的被吃掉，那颗升 1 级 ★
  没有额外的合成界面 —— 背包乱斗式背包里，"叠放"就是最自然的合成手势
- 结果等级 = **max(两边等级) + 1**，封顶 max_level。取 max 而不是相加：
  吃掉低级的不亏、吃掉同级的稳赚 1 级，但堆一把 1 级宝石**堆不出**满级
- 技能石和辅助宝石都能合；装备不参与（max_level = 1，没有"升级"可言）
- 目标满级时拒绝，且给专门的原因（"已经满级"），不报"那里已经有东西了"
- 规则实现在 `combat/gem_grid.gd`（merge_target / merge_reject_reason / merge）——
  能不能合和能不能放一样是背包规则，必须能单测；UI 只画金色预览格和发提示

**后果**：`run_tests.gd` 新增 14 条合成断言；冒烟测试用真实点击链路验了一遍
（拿起 → 叠上 → 升级 → 手上的消失）。拖拽预览悬停在同款上显示金色。

## ADR-019 金币不是奖励房型，每清一个战斗房自动进账

**背景**：金币房的问题在实践里很明显 —— 选它 = 这一步构筑不变强，
下一步的怪却照样更硬；它和「实物奖励」放在同一个选择维度上永远是劣势选项。

**决定**：
- ★ 删掉 `RewardKind.GOLD` ★（金币房、金币三选一整个不存在了），
  战斗房外显只剩 4 种：技能宝石 / 装备 / 辅助宝石 / 升级
- 每清一个战斗房**自动**给一笔金币：`RunContent.room_gold(step, rng)`，
  第 1 步 8~14、每往后一步 +3 —— 打到 Boss 前约攒 90~130 金，够逛两个商店
- 数额走 `rng_for("room_gold")` → 同一局同一步定死，读档重打拿到同一笔，刷不了钱
- 金币在**左侧面板常驻显示**（局模式；沙盒没有金币概念所以隐藏），
  战斗画面顶上的状态条保留；清房后的奖励面板顶部显示这一笔进账

**后果**：选房间回归纯粹的"要哪种成长"，金币变成稳定的节奏资源。
`_ensure_guarantees` 的补丁池从「金币或升级」缩成「升级」。

## ADR-020 法杖是技能的载体：宝石镶进法杖，箭头指着法杖

**背景**：项目主人要求"法杖作为技能的载体：每根法杖带一个镶嵌槽位，宝石镶进去，
指着法杖的辅助宝石对槽里的技能宝石生效，玩家初始获得一根法杖"。
这修改了 ADR-006 的"箭头直接指技能石"。

**决定**：
- ★ 技能宝石必须镶进法杖才能施放 ★ 裸放在网格里的技能宝石只是库存
  （不能施放、吃不到辅助、不出现在 Q 的切换列表里）
- `EquipItem` 增加 `socket_count`（法杖 = 1，其它装备 = 0）和 `socketed`
  （槽里那颗 SkillGem）。★ 槽里的宝石不占网格格子 ★ —— 拿起法杖它跟着走，
  存档时作为法杖条目的 `socket` 字段一起存
- 辅助宝石的箭头**指着法杖的任意一格**都算连上，辅助的是槽里的技能。
  法杖 1×2 / 1×3 → 周身 6~8 个箭头位，**法杖越长连线面积越大**，
  换更长的法杖本身就是构筑升级（取代了单格宝石"天然 4 连"的说法）
- 镶嵌手势和合成一致：手上的技能宝石点到法杖上 = 镶入；
  槽里是同款 = 合成升级（同网格叠放规则）；槽里是异款 = 交换（旧的回到手上）。
  取出走详情面板的「取出宝石」按钮（槽里的宝石点不到，必须有专门入口）
- 规则全部住在 `combat/`：`GemGrid.socket_target / socket_reject_reason / socket`、
  `supports_for / arrow_state / link_for / skill_items` 改为以法杖为中心；能单测
- 新装备「见习法杖」1×2：**零词缀**，价值就是那个槽。开局给它（镶着电球术）；
  它也进奖励池/商店 —— 买第二根法杖 = 能多带一个技能。
  ★ 零词缀还有一个工程原因 ★：`make_player()` 会把 `default_loadout()` 的词缀
  全部装上，见习法杖若带词缀，所有基准伤害测试的数值都要跟着改
- 存档版本升到 2（GemSave 和 RunSession 都是）：旧档的裸技能石在新规则下
  放不出技能，直接判旧版重开，不做迁移

**后果**：ADR-006 的"别加回 socket API"就此作废（有了实体载体，socket 是自然表达）。
`run_tests.gd` 的连线/存档/辅助测试全部改写为法杖语义，新增镶嵌规则一组断言；
冒烟测试用真实点击链路验了镶入 / 取出 / 交换。UI 上法杖中格画槽位圆环，
镶嵌预览是青蓝色（区别于合成金色 / 可放绿色）。

## ADR-021 一局 4 层，每层难度递增；金币每关都掉

**背景**：项目主人要求"游戏总共分 4 层，每层难度递增；金币改为每个关卡都掉落，
不存在专门的金币关卡"（后半句 ADR-019 已实现，这里把 Boss 关也补上）。

**决定**：
- `RunMap.FLOORS = 4`。★ 一层 = 一张 7 步的图 ★（复用原来的整套生成规则），
  每层第 7 步是这一层的守关 Boss；第 4 层的才是最终 Boss「骸骨领主」
- 层的流转在 `RunState`：守关 Boss 打赢 → 照常进 REWARD 领三选一 →
  `advance()` 时步数归零、层数 +1、按**层种子**重新生成下一层的图。
  层种子 = `hash([局种子, "floor", 层数])`，拿到局种子就能复现整局 4 张图；
  `rng_for` 的哈希也加入层数，否则每层同一步会掷出同一批奖励
- 难度递增全在 `RunContent` 的数值层（不写任何新战斗逻辑）：
  普通怪每深一层 +50% 生命 / +35% 伤害（INCREASED，和步内曲线相加）；
  Boss 模板按最终形态配，低层每差一层 -20% 生命 / -15% 伤害往下调，
  名字逐层升级（骸骨队长 → 男爵 → 将军 → 领主）
- ★ 金币每关都掉 ★：普通战斗房 `room_gold`（每深一层 +8），
  守关 Boss `boss_gold`（25~35 起，每层 +12）—— Boss 也是关卡，不能白打
- 存档加一个 `floor` 字段；缺字段的旧档按第 1 层读，不炸

**后果**：局的长度从 7 步变成 4 × 7 步；守关 Boss 房在地图上外显奖励类型
（和战斗房同款外显）。`run_tests.gd` 新增层流转 / 层种子 / 层数值曲线断言。

## ADR-022 R 键 = 重开一整局，不是重打当前房间

**背景**：局模式有自动存档，`R` 只做 `reload_current_scene()` 的话，
重载后 `prepare()` 会读到存档、续档回到当前步的选房阶段 ——
实际效果是"重打这一步"。项目主人明确要求 R 重开的是**整局**。

**决定**：
- `RunSession.abandon()`：删局存档 + 清内存里的局状态和读档暂存。
  World 的 R 键处理改成"局模式先 `abandon()` 再 reload"——
  重载后找不到存档，必然开全新的一局（新种子、第 1 层第 1 步、金币归零）
- 沙盒模式不变：R 只重载场景（沙盒没有"局"的概念，背包走 GemSave 照常保留）
- 代价：打炸了想"重打这一步"的后路没有了 —— 这是有意的，
  和"读档一律回到本步选房"（ADR-016）不冲突：**退出重进**仍然续档，
  只有**主动按 R** 才算放弃

**后果**：中途手滑按 R 会直接丢掉整局进度，操作提示改成「R 重开一整局」说清楚。
冒烟测试第八段补了"abandon 后 prepare 必须是全新一局"的断言。

## ADR-023 法杖的词缀只对槽里镶着的技能生效

**背景**：ADR-020 让法杖成了技能载体，但它的词缀仍按 ADR-010 的老规矩全局生效 ——
橡木法杖的「更多 30% 法术伤害」会加给**所有**技能，哪怕技能镶在别的法杖里。
项目主人要求：法杖只增幅镶在它槽里的那颗技能宝石。

**决定**：
- ★ 法杖的词缀改走 `skill_mods` 层（和辅助宝石同层、同命）★：
  `GemLink` 增加 `wand` 字段，`link_for()` 把法杖本身也打包进去，
  `GemLink.mods()` = 法杖词缀 + 辅助词缀 → `Player.rebuild()` 整层塞进 skill_mods。
  Q 切法杖时整层重建，词缀自动跟着"当前用的是哪根法杖"走
- `GemGrid.equip_mods()` 跳过法杖 —— equip 层只剩普通装备（头盔/靴子/戒指照旧全局）
- 空槽的法杖词缀没有作用对象：equip 层不进、link 是空的 → 哪层都不生效
- ★ `DemoContent.make_player()` 的基准口径不变 ★：它仍把橡木法杖的词缀放进
  equip_mods，等价于"正在用橡木法杖里的技能"的总加成 —— 全部老伤害断言原样成立。
  代价是拿它算"别根法杖里的技能"会比游戏内偏高，注释里写明了

**后果**：法杖从"又占格子又给全局加成"变成纯粹的**技能插槽 + 专属增幅**：
换法杖 = 换这个技能的增幅包，装备栏位的取舍更清晰。
`run_tests.gd` 新增作用域断言（equip 层无法杖 / 切法杖词缀跟着换 / 空杖零贡献）。

## ADR-024 等级改成 1~5；辅助宝石没有等级

**背景**：项目主人要求等级不照搬 PoE：技能宝石 1~5 级、辅助宝石干脆没有等级。
一局就 4 层、升级机会有限，1~20 的细密曲线在这个体量里每级毫无手感。

**决定**：
- ★ 技能宝石 `max_level = 5`，每级成长放大到 ≈PoE 的 4~5 级 ★
  （电球术每级 +28 点伤 / +4 消耗，5 级 ≈ 老曲线 20 级的数值；其余四颗同比）。
  合成（叠放/镶入同款）和升级奖励仍是一次 +1 级，规则不动
- 局开局宝石从 3 级降到 2 级（上限变小了，得留出升级空间；2 级 83 点伤够开荒）
- ★ 辅助宝石没有等级 ★：删掉 `mod_growth`，词缀数值 = 模板数值。
  `level / max_level = 1` 两个字段保留 —— 和 EquipItem 一个思路，
  让合成、升级奖励、`[-]/[+]`、存档 clamp 全都**自动**跳过它，不用到处写 if
- 重复的辅助宝石不再能合成 —— 它们的用处是给另一根法杖配同款连线
- 面板/手上提示对 `max_level <= 1` 的东西不显示等级；合成拒绝原因也不再对
  辅助宝石说"已经满级"（走普通的"那里已经有东西了"）
- 旧存档不清档：`clamp_level` 把超界等级自动夹回（15 级电球读回来是 5 级）

**后果**：`run_tests.gd` 加了一条防回退断言 —— 每颗主动技能石的每级成长
必须 ≥ 1 级点伤的 40%，防止有人把成长值改小回 PoE 曲线（5 级封顶配小成长
= 升级没手感）。顺带：新增两件回蓝装备（秘法腰带 3×1、蓝玉护符 1×1），
魔力回复从 Player 的硬常量改走属性系统（`S.MANA_REGEN`，基础 12/秒，
装备词缀在其上按四段式加成）；窗口从 1260×720 提到 1400×800
（内容 700×400 的整数 2 倍，像素均匀、文字按窗口分辨率渲染）。

## ADR-025 丢弃 = 拿在手上 + 两段确认的按钮

**背景**：背包 8×7 就 56 格，奖励和商店会一直塞东西进来，没有丢弃就只能"放弃奖励"。
但销毁是**不可逆**操作，误触把 5 级主力宝石丢了是不可原谅的。

**决定**：
- 手势：把东西拿在手上（左键点它）→ 点「丢弃」按钮**两次** ——
  第一次只发警告并记住"要丢的是哪一件"，第二次点**同一件**才真的销毁
- 任何点击（放下 / 拿起 / 右键）都会清掉确认状态：改了主意就要重新确认
- 丢一根槽里还镶着宝石的法杖，确认提示会写明"槽里的 XX 会一起丢掉"——
  不禁止（两段确认已是足够的保护），但必须说清代价
- 实现全在 UI 层（InventoryUI）：手上的东西本来就不在网格里，
  放掉引用即销毁，`rebuild()` 顺手把"没有它"的背包存盘。`combat/` 零改动

**后果**：什么都能丢（装备 / 宝石都行），丢掉唯一的法杖会让这局打不下去 ——
这是玩家自己的选择，按 R 重开就是。冒烟测试覆盖了两段确认和"改主意"路径。

## ADR-026 触媒：条件触发的特殊辅助宝石

**背景**：项目主人要求"触媒"——特殊辅助宝石，条件达成时自动触发连接的技能：
无施法动作、正常扣蓝、蓝不够不触发。条件：施加感电 3 次 / 点燃 3 次 /
冰冻 1 次 / 击中 5 次 / 移动 20 格 / 每 5 秒。

**决定**：
- `CatalystGem extends SupportGem`（combat/，纯逻辑）：住网格、带箭头、
  连线规则和普通辅助完全一样；不给词缀（mods 空），但魔力倍率照算。
  计数规则（advance / ready_to_fire / consume）全在这个类里，能单测
- ★ 进度封顶在门槛上 ★ —— 蓝不够时不许攒成多次触发，回一口蓝连环爆发就不是"节奏"了
- ★ 触发的是"箭头指着的那根法杖"，不限于当前法杖 ★ —— 触媒的意义就是
  副法杖挂条件自动打，主手照常手动。触发时 Player 临时把 skill_mods 换成
  目标法杖那套算投射物参数，算完换回（命中时用当时的当前词缀 —— 和手动切
  技能同一个已知误差）
- 事件流：击中 = Enemy.damaged（kind != "dot"）；施加异常 = Projectile 施加
  Debuff 时发 `behaviour("buff_<id>")`，World 转成触媒事件；移动 / 计时由
  Player 自己产。触发尝试统一在每物理帧的 `_pump_catalysts()` —— 蓝回来自动补
- ★「冰冻」按冰缓计 ★ 本项目冰系异常是冰缓（ADR-017），没有冰冻状态；
  门槛 1 次所以魔力倍率配最贵（×1.35）。「格」= 一块 16px 地砖，20 格 = 320px
- 6 颗触媒进 `all_supports()`（辅助池 10 → 16），随奖励/商店自然掉落

**后果**：`run_tests.gd` 新增计数/门槛/连线断言；冒烟测试走真实链路验了
"攒 5 次击中 → 触发扣蓝 → 蓝不够不触发 → 回蓝补触发"，并断言点燃事件
真的从投射物上报到了 behaviour_counts。触媒在 UI 里是紫色格子。

**补充（结算口径，项目主人拍板）**：★ 满足施加条件就计一次施加 ★ ——
判定点在投射物命中并通过几率判定的那一刻，和目标身上的状态**无关**：
同一目标重复施加（REFRESH 只续时间）、感电已叠满 3 层，都照样各计 1 次。
"3 次攻击同一目标、每次都够条件 = 3 次感电"。冒烟测试有专门的回归断言
（叠满层的目标再挨 2 发 → 事件 +2）。顺带修了"看不见计数在走"的问题：
触媒格子底部画实时进度条，详情面板停在触媒上时进度文本每 0.2 秒刷新。

**补充 2（防循环，项目主人拍板）**：★ 触媒触发出来的技能不能喂触媒 ★ ——
触发产物的击中 / 施加异常一律不给**任何**触媒攒进度（不只是触发它的那颗：
两颗触媒也能互相接龙成环，所以一刀切）。实现：`ProjectileState.from_trigger`
标记（纯逻辑，分叉出来的子弹继承），投射物上报施加事件、World 数击中时都看它。
移动 / 计时不受影响 —— 那是玩家行为，不是技能产物。等同 PoE 的
"被触发的技能不能再触发"。异常本身照常施加到目标身上，只是不计数。

## ADR-028 技能扩到 10 颗；房间分波刷怪；精英怪 = 底子加成 + 随机词条

**背景**：项目主人要求"增加更多技能，同时同一关卡内增加更多敌人，增加精英怪（属性更高，
且带有随机词条）"。三件事分别落在 data/、run 流程的表现层、以及一个新的纯逻辑类上。

**决定**：

- **技能 +5、辅助 +1（纯数据）**：冰矛（Ice Spear，暴击路）/ 翻滚岩浆（Rolling Magma，
  火系弹射打群）/ 焚烧（Incinerate，0.22 秒一发的贴脸火舌）/ 闪电之触（Lightning Tendrils，
  贴脸三叉扇）/ 精髓吸取（Essence Drain，**混沌** DoT 弹）+ 虚空操纵（Void Manipulation，
  更多混沌伤害）。全部沿用 PoE 中文版译名（见 AGENTS.md 名词表）。
  - 混沌是第五条构筑路：骷髅混沌抗 −30%，但三系元素辅助一颗都连不上，只吃虚空操纵和通用辅助
  - 精髓吸取的 DoT 是 **REFRESH 不叠层**（PoE 行为），否则配多重投射一发三中就是 3 倍 DoT
  - 精髓吸取**故意不带**【持续时间】标签：本项目 `DURATION` 只延长投射物存活、不改 Buff 时长，
    带了标签「延长持续」连上去就是一颗"装了没变化"的宝石（ADR-011 的教训）
  - 引导型技能（焚烧 / 闪电之触）本项目没有引导机制，用"极短施放时间 + 短命穿透弹"还原手感
- **房间分波刷怪**：`RunContent.enemies_for_step(step, floor)` 是这一房的**总数**
  （4 + 2·步 + 2·层，4~16，比老曲线多一倍以上）；`max_alive_for_step` 是**同时在场上限**
  （4~8）。World 一次配好整房名单（`room_roster`），先放满一波，剩下排队，
  死一只隔 `reinforce_delay`（0.9 秒）补一只。场地只有 400×400，16 只一起上是围殴不是战斗。
  Boss 房不分波：Boss + `boss_escorts`（2 + 层数）只护卫一次到场
- **精英怪**：`combat/monster_affix.gd`（纯逻辑：一条词条 = 名字 + 一组词缀 + 可选的
  近战附带异常 + 体型倍率）+ `data/monster_affixes.gd`（12 条词条池）。
  精英 = 同步同层普通怪 + 底子（+80% 生命 / +30% 伤害，INCREASED 与成长曲线相加）
  + `affix_count_for_floor`（前两层 1 条、后两层 2 条）条互不重复的随机词条，
  名字变成「迅捷·坚韧 骷髅战士」。每房 `elites_for_step` 只（第 1 层第 4 步起才有），
  **排在名单末尾压轴**。词条用 `rng_for("elite")` 抽 → 同局同房定死，读档重打刷不了词条
  - ★ 狂暴词条用 **FLAT** 攻速 ★：普通怪基础攻速是 0，INCREASED 在 0 上是恒真数据
  - 石肤（承伤 −25%）和感电在同一个 INCREASED 乘区相加 → 感电能反制它，是 PoE 式的克制关系
  - 爪类词条（灼热之爪 / 霜爪 / 雷爪）让怪也能给玩家上异常。怪用的火 DoT 是单独一条
    `buff_scorching_claw`（20/半秒、REFRESH），不复用玩家的点燃（40/半秒、独立叠加）——
    量级不同，将来调玩家点燃也不该连带改怪
  - 顺带修了一个从没走到过的路：玩家被 DoT 打死不发 `died`。以前没有怪能给玩家上 DoT
- **表现层**：精英金色调、体型 ×1.25（巨型再 ×1.35）、头顶写词条名、血条更宽；
  `CombatEntity.affixes` 只是清单（词缀早进了 gear_mods，source = 词条 id），
  表现层靠它画名字、判断爪类。沙盒模式每 4 只来一只精英，方便看外观
- 新宝石的图标是程序生成的占位图（`assets/icons/`，与老图同尺寸 78×78），
  风格比手绘的粗，等有真美术时按 id 同名替换即可

**后果**：主动 10 / 辅助 22（16 普通 + 6 触媒），全部自动进奖励池、商店、控制台。
`run_tests.gd` 新增 5 组断言（新技能参数与连接规则 / 混沌 DoT / 房间编制曲线与名单确定性 /
词条池逐条数值 / 精英底子与词条数），冒烟测试新增第九段：真实选房链路里验
"第一波只放到上限 → 死一只补一只 → 精英压轴且长得像精英 → 16 只全清才算清房 →
爪类 DoT 能烧死玩家并正确触发死亡"。

## ADR-029 技能扩到 16 颗；「新星」= 一圈 360° 的短命穿透弹；图鉴大过背包后自动补齐改为"能塞多少塞多少"

**背景**：项目主人要求"需要更多技能"。10 颗全是朝鼠标方向飞的投射物，再堆同类的收益递减；
TASKS 里挂着的「范围技能（新星）」一直没做，因为总以为要写一套新的范围机制。

**决定**：

- **技能 +6（纯数据）**：裂雷之矛（Crackling Lance，≈390 像素贯穿全场的重单发）/
  寒冬之眼（Eye of Winter，唯一天生分叉）/ 灵魂撕裂（Soulrend，穿透一切的轻混沌 DoT，
  和精髓吸取的 DoT 是不同 id、可共存）/ 虚空匕首（Ethereal Knives，唯一的**物理**法术）/
  冰霜新星（Ice Nova）/ 电击新星（Shock Nova）
- ★ **新星不需要新机制** ★：一次 N 发、STEP 模式 360/N 度一发、速度 × 存活 ≈ 90 像素、
  穿透一切 → 就是一个围着自己炸开的圈。「多重投射」= 圈更密，「冰霜增强」照常连。
  故意**不带**【持续时间】标签（半径就是它的代价，同冰霜脉冲）。`AREA_OF_EFFECT` 属性
  仍然没人用 —— 将来要做"范围提高"，把新星的 duration 接到那条属性上即可
- **物理法术的账**：虚空匕首不吃抗性（抗火词条对它无效），但吃护甲，而护甲对小刀减免大
  （`armour / (armour + 5×伤害)`）→ 单刀点伤配得重（170），升级后减免比例还会下降。

- 引导型 / 有特殊机制的 PoE 技能（裂雷之矛的充能、寒冬之眼的冰片）本项目一律用
  "现有投射物参数的组合"还原手感，不为单颗技能写逻辑
- **图鉴 45 件 > 背包 56 格能装的**（装备 18 格 + 38 颗宝石 = 正好 56）：
  `GemSave.fill_missing` 改成大件先放（小宝石先撒满网格，3×1 的腰带就再也塞不进了 ——
  冒烟测试真的红过：缺 arcane_belt）；放不下的静默跳过。沙盒里想要哪件用控制台生成。
  对应单测改成"要么全补齐，要么补到 1×1 都塞不下为止"（探针在副本上放，不弄脏原网格）
- 译名不确定的两颗：裂雷之矛（Crackling Lance）、电击新星（Shock Nova）——
  按记忆中的国服译名取的，**没有查证**。项目主人认得的话请纠正，改 id 之外的名字不影响存档

**后果**：主动 16 / 辅助 22。`run_tests.gd` 新增两组断言（六颗新技能的定位与连接规则 /
新星整圈均匀无缺口无重叠、半径、标签），冒烟测试的控制台筛选计数同步。
沙盒默认背包只剩 2 格空位。

## ADR-030 范围技能有自己的管线（AreaSpec），不再用一圈投射物冒充

**背景**：ADR-029 把新星做成"一圈 12 发 360° 的短命穿透弹"。项目主人指出这是取巧：
不是所有技能都该走投射物逻辑，新星这类显然不是投射物。它确实有真问题 ——
「多重投射」「穿透」这些投射物辅助能连上新星（语义不对）、圈的边缘有缝、
一只怪站在两道弹之间可能被打两次或漏掉、`AREA_OF_EFFECT` 属性还是没人用。

**决定**：

- **两条平行的管线**：投射物 = 飞出去撞到谁算谁（`ProjectileSpec`）；
  范围 = 以某个点为中心画圈、圈里的**全部**目标同时各结算一次命中（`combat/area_spec.gd`）。
  `SkillSpec` 加 `area_radius / area_origin / area_delay / area_range`，`with_area()` 填；
  `is_area()` 和 `is_projectile()` 互斥（一个技能不同时是两者，火球的"命中爆炸"以后再说）
- **AreaSpec 是纯逻辑**：谁在圈里由表现层喂 `[{id, dist}]`、它只比大小（和弹射选目标一个做法）。
  ★ 「范围效果」放大的是**面积**，半径按平方根走 ★（PoE 口径；直接乘半径的话 +100% = 4 倍面积）。
  `AREA_OF_EFFECT` 的基础值是 1.0 倍率，INCREASED / MORE 都在它上面算 —— 这条属性终于有人用了
- **延迟走「持续时间」属性**：风暴呼唤带 DURATION 标签、延迟 1.2 秒，「延长持续」连上去
  落雷更慢 —— 这是 PoE 的真实行为，不是恒真数据，是一条会让人掂量的连接。新星延迟 0
- **表现层 `game/area_burst.gd`**：纯代码画圈的计时器。有延迟先画预警圈（外圈 + 从中心涨满的
  实心），到点发 `exploded`；World 接信号才结算（期间怪走进走出圈都算数），然后画扩散的冲击波淡出。
  结算在 `World._resolve_area()`：和投射物**同一条五步管线**、同一套异常几率、同样喂触媒
  （触发产物不喂，ADR-026），`behaviour_counts` 多了 `area / area_hits`
- `Player.cast_requested` 多带 `aim`（鼠标在世界里的点）—— 「指哪打哪」要它；
  `catalyst_triggered` 同时带 `pspec / aspec`（一个非空一个 null），触媒触发的风暴呼唤砸最近的怪
- **内容**：冰霜新星 / 电击新星改成真范围（去掉【投射物】标签），新增风暴呼唤
  （Storm Call，指哪打哪 + 1.2 秒延迟 + 大单发）；辅助 +2：增大范围（ADR-011 删过一次，
  那时它没事可干；现在有了）、集中效应（更少 30% 范围、更多 40% 范围伤害）
- **图鉴 48 件 = 59 格 > 背包 56 格**：沙盒的"自动补齐全家桶"数学上不可能了。
  规则维持 ADR-029 的"补到塞不下为止"，冒烟测试改成"要么一件不少、要么 1×1 都放不进去"。
  沙盒里想要哪件用控制台生成（ADR-027）

**后果**：主动 17 / 辅助 24。`run_tests.gd` 新增两组断言（AreaSpec 的半径平方根缩放 / 圈内判定
含边界与去重 / 延迟吃持续时间 / 射程夹取；范围技能的连接规则 + 两颗新辅助的乘区），
冒烟测试新增第七段：真实施法链路里验"新星瞬发且**不产生投射物**、圈里的怪立刻掉血冰缓；
风暴呼唤 0.3 秒时还没掉血、1.2 秒后才劈"。ADR-029 里关于"新星 = 一圈弹"的段落作废。

## ADR-031 范围管线加脉冲与连环；辅助宝石分三档：普通 / 崇高 / 血脉

**背景**：项目主人要求"更多与范围有关的技能与辅助宝石，参考 PoE 的血脉宝石以及火炬之光的崇高 / 华贵辅助"。
查证：「血脉宝石」= 流放之路 2 的血脉辅助宝石（Boss 掉落的具名辅助，效果独特、改变技能运作方式）；
「崇高 / 华贵」= 火炬之光：无限里更高稀有度的辅助技能（效果比普通款强、常带负面）。
（来源：[游侠网 血脉辅助宝石图鉴](https://gl.ali213.net/html/2025-9/1698139.html)、
[TapTap 崇高/华贵讨论](https://www.taptap.cn/moment/603009250209303938)）

**决定**：

- **范围管线两个新机制**（纯逻辑在 `AreaSpec`，表现在 `AreaBurst`）：
  - **脉冲**：一个圈炸 N 次（`SkillSpec.area_pulses / area_interval`）。次数 = （技能基础 + 「脉冲次数」FLAT 词缀）
    × 「持续时间」倍率，四舍五入、至少 1 —— 延长持续 = 多炸几次，和 PoE 烈焰风暴"持续越久落得越多"一致。
    `AreaBurst` 每炸一次发一次 `exploded`，每次都是一轮完整结算
  - **连环**：沿施法方向前后各多几个圈（`AREA_CASCADE` FLAT），位置前后交替 [+1, −1, +2, −2 …]
    由纯逻辑给出、像素间距（1.2 个半径）由 World 乘。参考 PoE 的 Spell Cascade，名字是本项目自己起的
  - `CombatStat` 新增 `AREA_PULSES / AREA_CASCADE`
- **范围技能 +3**：烈焰风暴（Firestorm，指哪打哪、0.4 秒后 6 次脉冲、40% 点燃）/
  漩涡（Vortex，以自己为中心、4 次脉冲、冰缓）/ 瘟疫（Contagion，指哪打哪、瞬发、圈里每人一份混沌 DoT，
  第三个混沌 DoT id，三者可叠）。范围技能共 6 颗、主动 20 颗
- **普通辅助 +2**：缩短持续（Less Duration：更少 40% 持续、更多 10% 伤害）、连环范围（+2 圈、更少 20% 伤害）
- ★ **辅助宝石分三档**（`SupportGem.tier`）★
  - **普通**：奖励池 / 商店随处可得（原有的全部）
  - **崇高**（参考火炬的崇高/华贵）：普通款的加强版，效果翻倍、各带一条负面、蓝更贵。4 颗：
    崇高·增大范围（面积 +100%、伤害 −15%）/ 崇高·集中效应（伤害 +65%、范围 −50%）/
    崇高·缩短持续（持续 −70%、伤害 +25%）/ 崇高·连环范围（+4 圈、伤害 −35%）。
    **第 2 层起进奖励池、第 3 层起上货架（45 金）** —— 第 1 层是孤杖孤石的开荒期，负面那时候只是坑
  - **血脉**（参考 PoE2 的血脉宝石）：具名、独一份、**不进任何池子**，只有守关 Boss 必掉一颗
    （`RunContent.boss_lineage`，用 `rng_for("lineage")` 从没拿到的里面抽 → 同局同 Boss 同一颗；
    一局 3 个守关 Boss、3 颗血脉，正常打法刚好集齐）。魔力倍率 ×1.0，代价写在词缀里。3 颗：
    格里姆之震（面积 +60%、伤害 +20%、范围技能施法速度 −25%）/ 艾拉之脉动（脉冲 +2，新星变三连炸；范围 −25%）/
    塞洛斯之瞬（带持续时间的范围技能延迟 −75%；范围 −20%）。**名字是本项目自己起的**，不是 PoE2 的原名
  - 不重新分类触媒：它仍是"特殊辅助"，tier = NORMAL
- **不能让 Boss 掉的血脉丢了**：不占三选一的位置，直接 `place_anywhere` 进背包；放不下就记在
  `World._pending_lineage`，奖励面板提示"先腾一格"，`_leave_step` 会拦着不让走，直到放进去
- `all_supports()` 仍只含普通（奖励池 / 商店 / 老计数不变）；`all_sublime()` / `all_lineage()` 分开；
  `all_gems()` 三档都含（存档 / make_gem / 控制台靠它）。控制台多一档「崇高/血脉」筛选。
  UI：崇高金色格、血脉绯红格，tooltip 标层级

**后果**：主动 20 / 普通辅助 26（20 + 6 触媒）/ 崇高 4 / 血脉 3。`run_tests.gd` 新增三组断言
（脉冲次数吃词缀与持续时间、连环位置；三颗新技能与三个混沌 DoT 共存；三档的字段、每颗崇高真的比普通强且真的有负面、
每颗血脉的效果与代价、按层进池 / 上架、Boss 掉落不重复且同种子同颗）。冒烟测试：第七段加烈焰风暴
"一个圈炸了 6 次"，新增第十段"守关 Boss 房 Boss + 护卫到场 → 打赢 → 血脉进背包且正是种子定的那颗 → 进第 2 层"。
图鉴 60 件，沙盒背包的自动补齐断言改成"缺的全是 1×1 宝石（大件先放，装备一件不少）"。

## ADR-032 近战武器 + 攻击技能：武器是攻击技能的载体，近战 = 面前的圈，出手走攻速

**背景**：项目主人要求"搬运更多 PoE 技能保证多样性，也可以添加近战技能，并加入近战武器"。
此前 31 → 20 颗技能全是法术、全镶法杖、全走施法速度；`ATTACK` / `MELEE` 标签和 `ATTACK_SPEED`
属性只有怪在用。

**决定**：

- ★ **武器 = 攻击技能的载体** ★ 和法杖一模一样的槽（`socket_count = 1`），只是
  `EquipItem.socket_tags` 不同：法杖 = SPELL、武器 = ATTACK。`accepts_gem()` 判，
  `GemGrid.socket_reject_reason()` 拒绝并说明原因（"铁剑的槽只收攻击技能"）。
  火球镶不进铁剑、重击镶不进法杖 —— **载体决定技能类型**。存档、镶嵌手势、Q 切换全部复用
- **武器伤害走 FLAT**：攻击技能自己的点伤很低（32~95），武器上的「增加 N 点攻击伤害」
  （FLAT，要求 ATTACK）加在点伤上再乘四段式。走 skill_mods 只给槽里那颗技能（同 ADR-023）——
  换武器 = 换这个技能的伤害底子。不做 PoE 的"武器伤害有效度"，伤害公式一处实现的规矩不动。
  武器的所有词缀都要求 ATTACK：放背包里对法术零影响；`default_loadout()` 显式排除武器，基准角色不变
- **近战 = 范围管线的 `Origin.FRONT`**：面前 `range` 像素处的一个圈（重击 22 处半径 26 的小圈；
  横扫 30 处半径 45；重锤猛击 45 处半径 60）。不写第三条管线 —— 挥砍就是"打到面前一片"。
  单体近战（重击 / 冰霜之锤 / 毒蛇打击 / 双重打击）**不带【范围】标签**：圈小到不该吃增大范围；
  横扫 / 重锤猛击 / 旋风斩 / 炼狱之击 / 静电之击带。`AreaBurst` 给近战画成朝向前方的 200° 扇形（只是画法）
- **出手间隔按标签选属性**：`Player._try_cast` 攻击走 `ATTACK_SPEED`、法术走 `CAST_SPEED`
  （`DamagePipeline.actions_per_second` 本来就这样）。「迅捷施法」「法术节魔」要求【法术】，连不上攻击
- **技能 +11**：近战 9（重击 / 横扫 / 重锤猛击 / 双重打击 / 旋风斩 / 炼狱之击 / 冰霜之锤 / 静电之击 /
  毒蛇打击）+ 灵体投掷（攻击投射物：穿透一切，吃武器伤害也吃投射物辅助）+ 冰川之刺
  （法术，`Origin.FRONT` + 天生连环 2 = 三个圈排成一线；`SkillSpec.area_cascade` 新字段）。
  双重打击 / 旋风斩 / 静电之击用脉冲；毒蛇打击的中毒是 **INDEPENDENT 独立叠加**（PoE 的中毒），
  攻速就是毒量 —— 和精髓吸取（REFRESH）分工。旋风斩带【持续时间】：延长持续 = 多转几圈
- **武器 +4**：铁剑 1×3（+70 / 攻速 +10%）、战斧 2×2（+110 / 近战 +15% / 攻速 −10%）、
  巨锤 2×3（+170 / 攻击的范围 +30% / 攻速 −20%）、匕首 1×2（+45 / 攻速 +25% / 攻击暴击 +60%）。
  UI 里武器是铁灰格，和法杖 / 防具的金褐分开
- 简化：元素近战（炼狱之击 / 冰霜之锤 / 静电之击）整下按技能元素结算，武器的物理伤害不做"转化"。
  译名：重锤猛击（Ground Slam）按记忆取的，没查证；其余（重击 / 横扫 / 双重打击 / 旋风斩 / 炼狱之击 /
  冰霜之锤 / 静电之击 / 毒蛇打击 / 灵体投掷 / 冰川之刺）是 PoE 国服的名字

**后果**：主动 31（20 法术 + 10 攻击 + 冰川之刺），走范围管线的 16 颗（7 范围法术 + 9 近战），装备 11 件。
`run_tests.gd` 新增两组断言（槽类型与拒绝原因、武器词缀只给槽里的技能且 equip 层没有它、换武器换底子、
基准角色不含武器、存档往返；近战的 FRONT 参数、出手走攻速而施法速度无效、脉冲、异常、中毒独立叠加、
灵体投掷、冰川之刺）。冒烟测试第七段加近战：真实镶嵌规则放行横扫、`_try_cast` 的冷却按攻速算
（先于摆怪 —— headless 鼠标在 (0,0) 会朝左挥）、面前的怪挨打而背后的不挨、不产生投射物。
`_test_area_skills` 的"范围技能必带【范围】标签"改为"没有标签的必须是半径 ≤ 30 的近战小圈"。

**补充（圈跟着人走，项目主人反馈）**：旋风斩的圈钉在施放点上，人走开圈还在原地 —— 那不是旋风斩。
加 `SkillSpec.area_follow`（`with_follow()`）→ `AreaSpec.follow`；`AreaBurst.follow = player`，每帧把圈挪到
施法者身上（保留施放时的相对偏移，双重打击的第二刀仍在面前），结算读圈**此刻**的位置。
旋风斩 / 双重打击跟着走；漩涡 / 静电之击 / 烈焰风暴按 PoE 的行为留在原地。冒烟测试：放旋风斩后把玩家挪 60 像素，
3 帧后圈必须在脚下。

## ADR-033 引导技能：按住持续施放、逐段扣蓝、引导中不能切技能

**背景**：项目主人指出旋风斩这类应该是引导技能 —— 期间持续消耗蓝、不能主动使用其他技能，对应伤害要提高。
此前旋风斩做成"一次施法转 5 圈"，焚烧 / 闪电之触做成"施放极快的普通技能"，都没有引导的代价。

**决定**：
- `SkillSpec.channel`（`with_channel()`）。★ 不写第二条施法路径 ★：按住 → 冷却到了再放一段，
  这条路普通技能本来就在走；引导只多一个**状态**：按住且上一段放出去了 = `Player._channeling`，
  松手 / 蓝不够放不出 / 切了技能 = 结束。`_try_cast` 改成返回 bool 供它判断
- 引导中 `Q` 无效（`_unhandled_input` 看 `_channeling`）。触媒是自动的，不受影响
- `cast_time` 在引导技能上 = 每段时长（÷ 攻速或施速），`mana_cost` = 每段扣蓝 → "持续消耗"自然成立。
  旋风斩每段 0.25 秒 4 蓝 = 16 蓝/秒，比基础回蓝 12 高，蓝就是它的计时器
- 三颗引导：旋风斩（每段 1 圈、跟着人走，去掉【持续时间】标签，每圈 32 → **55**，每秒基础 178 → 220，
  而且武器伤害每 0.25 秒吃一次）；焚烧（42 → 48）；闪电之触（75 → 85）。伤害提高是引导代价的对价
- HUD 状态行标「引导中 / 引导：按住不放」，宝石面板写明每段时长和扣蓝

**后果**：`run_tests.gd`：引导技能 3 颗、旋风斩的段长 / 扣蓝 / 伤害门槛、延长持续连不上旋风斩。
冒烟测试第七段加引导链路：真实按住 → 引导中且扣蓝 → 按 Q 技能没切走 → 0.25 秒后又扣一段 →
松手引导结束、Q 恢复 → 没蓝按住也引导不起来。

## ADR-034 扇形 / 光束范围；焚烧、闪电之触、裂雷之矛从投射物改回范围

**背景**：项目主人指出投射物技能太多，有些该是范围技能。按 PoE 原作核对：焚烧（3.3 起）、闪电之触是
Spell + AoE + Channelling 的锥形，裂雷之矛是 Spell + AoE 的光束 —— 都不是投射物，之前用"短命穿透弹"冒充。

**决定**：
- 范围管线加**扇形**：`SkillSpec.area_arc_deg`（`with_arc(deg)`），360 = 整圆。扇形以施法者为中心
  （`Origin.SELF`）朝施法方向张开，半径就是长度。`AreaSpec.hits()` 的候选多带一个 `angle`
  （目标方向和朝向的夹角），超过 arc/2 的不算；贴身（dist ≤ 4）不看角度；没带 angle 的老调用方按整圆算。
  「增大范围」放大的是长度（半径 × √面积倍率），角度不变。`AreaBurst` 已有扇形画法，直接用
- 三颗改回范围：焚烧 40° × 110、闪电之触 60° × 120（都是引导，每段一次扇形结算）、裂雷之矛 14° × 320（光束）。
  去掉【投射物】标签、加【范围】标签 → 多重投射 / 穿透连不上了，增大范围 / 集中效应连得上。
  数值不变（伤害、消耗、段长照旧）
- 投射物 15 → 12，走范围管线 16 → 19（其中带【范围】标签 15）。投射物不再是最多的一类

**后果**：`run_tests.gd` 加扇形判定断言（正前方 / 边缘内 / 贴身中，扇形外 / 背后 / 太远不中；整圆忽略角度；
老候选格式不炸），三颗技能的断言改写；投射物数量上限断言。

## ADR-035 连锁 ≠ 弹射：连锁不重复命中、连锁中投射物 +500% 速度

**背景**：项目主人要求把「连锁」和「弹射」区分开：连锁无法重复命中同一敌人，连锁时有 500% 更多投射物速度。
此前电弧用的是弹射（可以两只怪来回弹），和翻滚岩浆 / 弹射支援是同一套。

**决定**：
- 两套次数、两套规则：`CombatStat.LINK_COUNT`（连锁次数）/ `SkillSpec.base_link` / `ProjectileSpec.link_count`，
  搜索半径和弹射共用 `chain_range`
- `ProjectileState`：`Action.LINK`，优先级 **穿透 > 分叉 > 连锁 > 弹射**（电弧连了弹射支援 = 先跳完 3 次连锁再来回弹）。
  `pick_link_target()` 排除**所有** `hit_ids`（不回头），取最近；没有新目标 = 连锁到此为止、投射物消失。
  `speed_multiplier()`：跳出去之后 ×(1 + 5.0)，表现层每帧乘 —— 电弧的跳跃几乎瞬间
- 弹射维持原样（`pick_chain_target` 可以回头，两只怪来回弹是弹射流的单体伤害来源）
- 电弧改为天生连锁 3、弹射 0；新增「连锁支援」（+2 连锁、更少 20% 伤害、×1.40）和「弹射支援」并列：
  连锁打群更快更稳，弹射打单体更狠
- 面板 / 伤害报告 / describe 分开写"弹射 N"和"连锁 N"

**后果**：`run_tests.gd` 新增一组断言（不回头、只剩打过的就结束、×6 速度、弹射对照会回头且不加速、
四级优先级、分叉继承、两颗支援叠在电弧上各算各的）。冒烟测试加电弧段：两只怪排成一列，一发电弧连锁到第二只。

## ADR-036 同质化技能的差异化；敌人碰撞圈盖住身子；连锁追踪目标

**背景**：项目主人指出太多同质化技能，连锁命中率低、敌人碰撞格似乎有问题。
查实：敌人的碰撞圈是脚下半径 5 的小圆，精灵画在上面 16 像素高 —— 瞄着身子打的弹从头顶飞过；
连锁 +500% 速度后每物理帧飞 30 像素，5+4 像素的圈直接被跳过（隧穿）。

**决定**：
- **碰撞**：敌人碰撞圈改成半径 7、中心 (0, −6)，盖住身子。连锁改成**追踪**：`Projectile._link_target`，
  每帧朝目标此刻的位置飞，一步之内能到就直接贴上去 —— 高速不再隧穿
- **差异化**（每颗技能一个别人没有的东西，全部是小机制、复用现有管线）：
  - 火球 / 翻滚岩浆：**命中爆炸**（`SkillSpec.with_explosion` → `ProjectileSpec.explode_radius`），
    在命中点炸一圈打周围**其他**敌人。带 `area_radius` 的投射物不再算范围技能（`is_area()` 排除投射物），
    AREA 标签终于有实际意义；吃「增大范围」
  - 冰矛：**变形**（飞 70 像素后速度 ×2、暴击 ×3 → 60%），照 PoE。近处平平、远处爆头
  - 灵体投掷：**回旋**（存活过半掉头飞回施法者，命中记录清空 → 回程再打一遍）
  - 灵魂撕裂：**随行光环**（跟着投射物的 45 像素圈，每 0.3 秒结算，`AreaBurst.follow` + `die_with_follow`），
    不用撞到人；和精髓吸取（单体 DoT 弹）彻底分开
  - 电击新星：**环**（`area_inner_radius` 45、外 120、伤害 200），贴身打不到；和冰霜新星（实心圆）互补
  - 焚烧：**蓄力**（`channel_ramp`：每段叠 1 层 +12% 火焰法术伤害、8 层封顶、0.6 秒不续就掉），30° × 130 窄而长；
    闪电之触改 100° × 90 宽而短 —— 两颗引导锥一个"站桩烧"一个"贴脸扫"
  - 瘟疫：**死亡扩散**（带瘟疫的怪死时传给 70 像素内的怪，`World._on_enemy_died`），照 PoE
  - 重锤猛击：从脚下出发的 100° 宽锥、长 95（横扫的两倍远）；冰霜之锤：70° 短锥、长 48、带【范围】标签、伤害略降
    —— 和横扫（面前圆）/ 重击（面前小圆）的形状区分开

**后果**：`run_tests.gd` 新增一组断言（爆炸半径与增大范围、变形阈值 / 倍率 / 分叉继承、回旋掉头与清空命中、
光环参数、环的内外沿判定与同比缩放、蓄力封顶与消退、锥形参数）；扇形 / 锥 / 计数相关的老断言按新数值改。
冒烟测试新增：火球命中爆炸打到弹道外 30 像素的怪；带瘟疫的怪死掉后身边的怪染上瘟疫。

## ADR-037 凡是打一个圈的都带【范围】标签；占位美术全部换成授权素材

**背景**：项目主人指出"部分应该有范围词条的没有范围词条"，以及"大部分美术资产需要更新，不能使用临时资源"。

**决定**：
- ★ **走范围管线的技能一律带【范围】标签** ★：重击 / 双重打击 / 毒蛇打击（面前的小圈）、灵魂撕裂（随行光环）补上。

  - 最初自带的 19 张图标不动
  - `assets/CREDITS.md` 记来源与署名（CC-BY 发布时必须保留）；`pixel_art.gd` 改成"真素材优先、缺了退回字符画"，
    字符画只为 headless 测试和防炸留着
- 风格上：原有 19 张是 PoE 式宝石渲染、新图标是手绘风、角色是 16 像素点阵 —— 三种风格并存。
  统一风格需要项目主人提供或生成一整套；替换只要覆盖同名文件

**补充（图标按类型分样式，项目主人反馈"技能和辅助宝石的样式要区分"）**：Painterly 图集自带一套 frame-0 边框，
按宝石类型套不同颜色：技能天蓝框；辅助绿框 + 20% 绿色罩色 + 35% 去饱和；崇高橙框 + 金色罩色；血脉红框 + 红色罩色。

32×32 tiles（CC0）：法师（wizard）、骷髅（skeleton_humanoid_small）、Boss 用远古巫妖（ancient_lich，`PixelArt.boss()`）。
