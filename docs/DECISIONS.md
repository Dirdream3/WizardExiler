# 设计决策记录（ADR）

> ★ **改动之前先在这里搜一下** ★
> 这里记的都是**想清楚之后才这么做的**。看着奇怪 ≠ 写错了。
> 如果你（人或 AI）觉得某条决定是错的，**改之前先在 PR 里说明理由**，别默默"顺手修好"。

格式：**背景 → 决定 → 后果**。新决定追加在最后，不要插在中间（减少 diff 冲突）。

---

## ADR-001 `combat/` 零引擎依赖

**背景**：PoE 式词缀交互复杂，不写测试必炸。但 Godot 的 Node 很难在 headless 下测。

**决定**：`combat/` 里不许出现 `Node` / `Sprite` / `Camera` / 场景坐标 / `FileAccess` / `get_tree()`。
表现层**持有** `CombatEntity`，不是继承它。

**后果**：
- ✅ 271 个单元测试能存在
- ✅ 能做离线 DPS 计算器；将来联机能搬到服务器验算
- ⚠️ 文件读写、找最近的敌人这类事必须由 `game/` 喂进来（`GemGrid.from_data` 收一个 `resolve` 回调而不是直接查图鉴，就是这个原因）

## ADR-002 四段式公式只有一处实现

**背景**：`INCREASED`（提高，相加共用一个乘区）和 `MORE`（更多，各自连乘）如果混成一个 float，
整个装备构筑的深度就没了。这是 PoE-like 项目最常见的返工点。

**决定**：公式只写在 `StatSet.breakdown_layered()` 一处，所有算伤害的地方都走它。

**后果**：任何"我这里简单算一下就行"的想法都要拒绝。有第二处实现，数值一定对不上。

## ADR-003 标签用位掩码，派生标签独立占一位

**背景**：每帧要做成千上万次标签匹配。而且「元素伤害」这种派生标签容易写错。

**决定**：标签是 `int` 位掩码；`ELEMENTAL` **独立占一位**，由 `CombatTags.normalize()` 在查询时自动补上。

**后果**：不能写 `ELEMENTAL = FIRE|COLD|LIGHTNING` ——
匹配用的是 `has_all`（要求全部包含），那样写会变成"必须同时是火+冰+电"，永远吃不到。

## ADR-004 技能石和 SkillSpec 分成两层

**背景**：`SkillSpec` 是"这一次施法用什么参数"，没有等级概念。但玩家手里的是一颗有等级、会成长的石头。

**决定**：`SkillGem`（等级 + 成长曲线 + 标签）通过 `build()` 展开成 `SkillSpec`。

**后果**：等级、辅助宝石的魔力倍率这些只属于宝石的概念，一点都不会漏进伤害公式。
`build()` 每次返回**新的** `SkillSpec`（`SkillSpec.duplicate()`），改返回值不会污染模板。

## ADR-005 「电球术」= PoE 的 Spark

**背景**：AI 把中文「电球」按字面理解成 Ball Lightning，凭空造了一个脉冲技能，返工一整轮。

**决定**：项目采用 **PoE 中文版的官方译名**。
- **电球术** = Spark（一次射 4 发乱窜的小球，撞墙会弹）← 本项目的标准技能石样板
- 闪电球 = Ball Lightning（已删除，见 ADR-011）

**后果**：见 [AGENTS.md 名词对照表](../AGENTS.md#2--名词对照表踩过坑务必先看)。
**拿不准英文原名就问，不要猜。**

## ADR-006 连接关系用「网格 + 箭头」，不用插槽

**背景**：一开始做的是 PoE 那种"技能栏三格，每格 1 主石 + 4 插槽"。
但项目主人想要「背包乱斗」那种网格背包。

**决定**：所有宝石住在同一张 8×7 网格里。辅助宝石带一个**箭头**，
**箭头指进哪颗主动技能石，就辅助哪颗**。`GemLink` 变成网格**算出来的结果**，
没有 `socket()` / `unsocket()`。

**后果**：
- ✅ "怎么摆"本身成了构筑的一部分
- ✅ 一颗辅助只有一个箭头 → 不可能同时辅助两个技能（规则天然自洽）
- ✅ 技能石只占 1 格 → 四面最多 4 个箭头位 → **PoE 的「4 连」是几何自然的结果，不是写死的上限**
- ⚠️ 想改连接只能去背包里挪宝石。**别再加回 socket API**

## ADR-007 战斗画面用 SubViewport 真正裁成正方形

**背景**：要"左边常驻 UI + 右边正方形战斗画面"。
最省事的做法是"拿不透明面板盖住左半边"，但那样怪物会跑到面板"下面"、边界是假的。

**决定**：战斗画面是真正的 `SubViewport`（400×400），场地里的一切都挂在它底下。

**后果**：
- ✅ 硬边界，怪物和投射物不可能跑到面板上面去
- ⚠️ SubViewport 有**自己的 World2D** → 场地里的一切（含墙）必须 `view.add_child()`
- ⚠️ 玩家问不到主窗口的鼠标 → `can_aim` 由 `GameWorld._process` 写进去

## ADR-008 `can_aim` 用几何判断，不用 `gui_get_hovered_control()`

**背景**：需要"鼠标在左边面板上时不施法"。

**决定**：`GameWorld._process` 里 `battle.get_global_rect().has_point(battle.get_global_mouse_position())`，
结果写进 `Player.can_aim`。

**后果**：★ **两边必须是同一个坐标系** ★
- `get_global_rect()` + `get_global_mouse_position()` —— 都是视口坐标（300~700）✅
- `get_rect()` + `get_local_mouse_position()` —— 前者父坐标、后者自身坐标 ❌

这个坑踩过一次（"只有屏幕最右边 100px 能施法"），冒烟测试现在有 6 条边界断言盯着。

## ADR-009 背包存档存 JSON，而且存 id 不存下标

**背景**：加了网格背包之后，"怎么摆"就是构筑本身。不存盘的话每次按 R 重开就全没了。

**决定**：
- 存 **JSON**（可读、可手改、出问题一眼看出哪不对），放 `user://backpack.json`
- 序列化在 `GemGrid.to_data/from_data`（纯逻辑，能单测），文件读写在 `game/gem_save.gd`
- **存「当前技能是哪颗宝石」的 id，不是 `skill_index`**

**后果**：
- `skill_index` 是 `skill_items()` 里的位置，而那个列表**按摆放位置排序** ——
  挪一下宝石、或者补进一颗新技能石，同一个下标就指到别人身上去了
- 读档做了四层容错（删掉的宝石 / 位置冲突 / 新增内容 / 文件损坏），因为宝石表还在改
- 测试必须在场景 `_ready` **之前**设 `GemSave.autosave = false`，否则跑一次测试就覆盖玩家存档

## ADR-010 装备和宝石同网格，放着就生效

**背景**：要加装备系统。可以做成独立的"装备栏"，也可以像背包乱斗那样放进同一张网格。

**决定**：装备住在同一张网格里，**只要在背包里就生效，不需要连箭头**。
宝石都只占 1 格，装备占多格（法杖 1×3、头盔 2×2）。

**后果**：
- ✅ "占地方"的取舍全压在装备身上：背包 56 格，装备摆得越舒服，留给"技能石 + 四面箭头"的空间越少
- ✅ 装备旋转有意义（法杖竖着 1×3 塞不进的地方，转成 3×1 就行）
- 词缀多了一层 `equip_mods`（见 ADR-012）

## ADR-011 删掉脉冲机制和「闪电球」

**背景**：ADR-005 那次误解造出来的 Ball Lightning 用了一套"沿途反复放电"的脉冲机制。
项目主人明确要求删掉。

**决定**：整套删除 —— `with_pulse` / `is_pulsing` / `PULSE_RATE` / `collides_with_enemies` /
`pulse_ticks` / `pulse_dps` / `max_pulses` / `Projectile._do_pulse` / 电场圈的画法 / 闪电球贴图。

**顺带删了**「增大范围」辅助宝石 —— 它唯一的作用是放大脉冲半径，
脉冲没了它就是一颗"装上去什么都不会变"的宝石，留着比删掉更误导人。

**后果**：`AREA_OF_EFFECT` 属性保留（以后做真正的范围技能还要用），但目前无人使用。

## ADR-012 词缀分四层，装备和辅助宝石那两层「整层重建」

**背景**：装备、辅助宝石、天赋的生效范围完全不同，混在一个 `StatSet` 里没法维护。

**决定**：`CombatEntity` 持有四层，查询时叠在一起算一次四段式：

| 层 | 内容 | 维护方式 |
|---|---|---|
| `gear_mods` | 天赋 / 被动树 | 不变 |
| `equip_mods` | 背包里的装备 | `Player.rebuild()` **整层重建** |
| `skill_mods` | 箭头连着当前技能的辅助宝石 | `Player.rebuild()` **整层重建** |
| Buff | 增益 / 减益 | `BuffContainer` 计时 |

**后果**：
- ✅ 背包一变就整层清空重填，不用追"哪一条该删"，也不会串味
  （箭头指着电球术的「多重投射」不会让火球术也变多发）
- ✅ 顺带修掉一个老问题：以前 `make_player()` 里硬写着 source 叫 `staff` / `ring_of_flame` 的词缀，
  但游戏里根本没这两件东西。现在它们是真装备，**id 保持不变**，所以角色总加成一点没变
  （老的伤害测试全部原样通过），但终于有实物了

## ADR-013 施放时间是「秒」，不是「倍率」

**背景**：`SkillSpec.cast_time` 原来注释成"耗时倍率"，含义模糊。

**决定**：它就是 PoE 技能石上印的**基础施放时间（秒）**。

```
每秒出手次数 = 施法速度倍率 ÷ 施放时间
```

**后果**：「提高施法速度」是缩短这个时间，不是改这个字段本身。
`Player._try_cast()` 里 `_cast_cd = skill.cast_time / speed`。

## ADR-014 不写恒真的断言

**背景**：曾经写过一条断言"SubViewport 鼠标 = 主视口鼠标 − 容器左上角"，
实测发现引擎是**按容器位置实时推算**的，这条永远成立。

**决定**：删掉，只留"值确实变了"这条有效的。

**后果**：写断言之前先问自己 —— **它可能红吗？**
恒真的断言比没有更糟，它给假信心。同理，探针脚本自己也要加断言
（曾经因为探针脚本没检查 `place()` 的返回值，把"脚本选错落点"误判成"存档功能坏了"）。

## ADR-015 文档拆成「给人看的」和「给 AI 看的」，但规约只有一份

**背景**：需要支持多人 + 多 AI 协作，同步到 GitHub。

**决定**：
- `AGENTS.md` —— **唯一的 AI 规约**，Cursor / Copilot / Codex 等通用
- `CLAUDE.md` —— 只是个指针，指向 `AGENTS.md`（Claude Code 会自动读它）
- `CONTRIBUTING.md` —— 人类的流程（环境、分支、提交、PR）
- `docs/` —— ARCHITECTURE（怎么组织的）/ DECISIONS（为什么）/ TASKS（在做什么）

**后果**：规约只有一份，不会出现"各家 AI 遵守不同规则"。
加新的 AI 工具时，只要让它读 `AGENTS.md` 就行。
