# 设计决策记录（ADR）

> ★ **改动之前先在这里搜一下** ★
> 这里记的都是**想清楚之后才这么做的**。看着奇怪 ≠ 写错了。
> 如果你（人或 AI）觉得某条决定是错的，**改之前先在 PR 里说明理由**，别默默"顺手修好"。

格式：**背景 → 决定 → 后果**。新决定追加在最后，不要插在中间（减少 diff 冲突）。

## ADR-001 `combat/` 零引擎依赖

**背景**：PoE 式词缀交互复杂，不写测试必炸。但 Godot 的 Node 很难在 headless 下测。

**决定**：`combat/` 里不许出现 `Node` / `Sprite` / `Camera` / 场景坐标 / `FileAccess` / `get_tree()`。
表现层**持有** `CombatEntity`，不是继承它。

**后果**：
- ✅ 271 个单元测试能存在
- ✅ 能做离线 DPS 计算器；将来联机能搬到服务器验算
- ⚠️ 文件读写、找最近的敌人这类事必须由 `game/` 喂进来（`GemGrid.from_data` 收一个 `resolve` 回调而不是直接查图鉴，就是这个原因）

## ADR-002 四段式公式只有一处实现

**背景**：`INCREASED`（提高，相加共用一个乘区）和 `MORE`（更多，各自连乘）如果混成一个 float，
整个装备构筑的深度就没了。这是 PoE-like 项目最常见的返工点。

**决定**：公式只写在 `StatSet.breakdown_layered()` 一处，所有算伤害的地方都走它。

**后果**：任何"我这里简单算一下就行"的想法都要拒绝。有第二处实现，数值一定对不上。

## ADR-003 标签用位掩码，派生标签独立占一位

**背景**：每帧要做成千上万次标签匹配。而且「元素伤害」这种派生标签容易写错。

**决定**：标签是 `int` 位掩码；`ELEMENTAL` **独立占一位**，由 `CombatTags.normalize()` 在查询时自动补上。

**后果**：不能写 `ELEMENTAL = FIRE|COLD|LIGHTNING` ——
匹配用的是 `has_all`（要求全部包含），那样写会变成"必须同时是火+冰+电"，永远吃不到。

## ADR-004 技能石和 SkillSpec 分成两层

**背景**：`SkillSpec` 是"这一次施法用什么参数"，没有等级概念。但玩家手里的是一颗有等级、会成长的石头。

**决定**：`SkillGem`（等级 + 成长曲线 + 标签）通过 `build()` 展开成 `SkillSpec`。

**后果**：等级、辅助宝石的魔力倍率这些只属于宝石的概念，一点都不会漏进伤害公式。
`build()` 每次返回**新的** `SkillSpec`（`SkillSpec.duplicate()`），改返回值不会污染模板。

## ADR-005 「电球术」= PoE 的 Spark

**背景**：AI 把中文「电球」按字面理解成 Ball Lightning，凭空造了一个脉冲技能，返工一整轮。

**决定**：项目采用 **PoE 中文版的官方译名**。
- **电球术** = Spark（一次射 4 发乱窜的小球，撞墙会弹）← 本项目的标准技能石样板
- 闪电球 = Ball Lightning（已删除，见 ADR-011）

**后果**：见 [AGENTS.md 名词对照表](../AGENTS.md#2--名词对照表踩过坑务必先看)。
**拿不准英文原名就问，不要猜。**

## ADR-006 连接关系用「网格 + 箭头」，不用插槽

**背景**：一开始做的是 PoE 那种"技能栏三格，每格 1 主石 + 4 插槽"。
但项目主人想要「背包乱斗」那种网格背包。

**决定**：所有宝石住在同一张 8×7 网格里。辅助宝石带一个**箭头**，
**箭头指进哪颗主动技能石，就辅助哪颗**。`GemLink` 变成网格**算出来的结果**，
没有 `socket()` / `unsocket()`。

**后果**：
- ✅ "怎么摆"本身成了构筑的一部分
- ✅ 一颗辅助只有一个箭头 → 不可能同时辅助两个技能（规则天然自洽）
- ✅ 技能石只占 1 格 → 四面最多 4 个箭头位 → **PoE 的「4 连」是几何自然的结果，不是写死的上限**
- ⚠️ 想改连接只能去背包里挪宝石。**别再加回 socket API**

## ADR-007 战斗画面用 SubViewport 真正裁成正方形

**背景**：要"左边常驻 UI + 右边正方形战斗画面"。
最省事的做法是"拿不透明面板盖住左半边"，但那样怪物会跑到面板"下面"、边界是假的。

**决定**：战斗画面是真正的 `SubViewport`（400×400），场地里的一切都挂在它底下。

**后果**：
- ✅ 硬边界，怪物和投射物不可能跑到面板上面去
- ⚠️ SubViewport 有**自己的 World2D** → 场地里的一切（含墙）必须 `view.add_child()`
- ⚠️ 玩家问不到主窗口的鼠标 → `can_aim` 由 `GameWorld._process` 写进去

## ADR-008 `can_aim` 用几何判断，不用 `gui_get_hovered_control()`

**背景**：需要"鼠标在左边面板上时不施法"。

**决定**：`GameWorld._process` 里 `battle.get_global_rect().has_point(battle.get_global_mouse_position())`，
结果写进 `Player.can_aim`。

**后果**：★ **两边必须是同一个坐标系** ★
- `get_global_rect()` + `get_global_mouse_position()` —— 都是视口坐标（300~700）✅
- `get_rect()` + `get_local_mouse_position()` —— 前者父坐标、后者自身坐标 ❌

这个坑踩过一次（"只有屏幕最右边 100px 能施法"），冒烟测试现在有 6 条边界断言盯着。

## ADR-009 背包存档存 JSON，而且存 id 不存下标

**背景**：加了网格背包之后，"怎么摆"就是构筑本身。不存盘的话每次按 R 重开就全没了。

**决定**：
- 存 **JSON**（可读、可手改、出问题一眼看出哪不对），放 `user://backpack.json`
- 序列化在 `GemGrid.to_data/from_data`（纯逻辑，能单测），文件读写在 `game/gem_save.gd`
- **存「当前技能是哪颗宝石」的 id，不是 `skill_index`**

**后果**：
- `skill_index` 是 `skill_items()` 里的位置，而那个列表**按摆放位置排序** ——
  挪一下宝石、或者补进一颗新技能石，同一个下标就指到别人身上去了
- 读档做了四层容错（删掉的宝石 / 位置冲突 / 新增内容 / 文件损坏），因为宝石表还在改
- 测试必须在场景 `_ready` **之前**设 `GemSave.autosave = false`，否则跑一次测试就覆盖玩家存档

## ADR-010 装备和宝石同网格，放着就生效

**背景**：要加装备系统。可以做成独立的"装备栏"，也可以像背包乱斗那样放进同一张网格。

**决定**：装备住在同一张网格里，**只要在背包里就生效，不需要连箭头**。
宝石都只占 1 格，装备占多格（法杖 1×3、头盔 2×2）。

**后果**：
- ✅ "占地方"的取舍全压在装备身上：背包 56 格，装备摆得越舒服，留给"技能石 + 四面箭头"的空间越少
- ✅ 装备旋转有意义（法杖竖着 1×3 塞不进的地方，转成 3×1 就行）
- 词缀多了一层 `equip_mods`（见 ADR-012）

## ADR-011 删掉脉冲机制和「闪电球」

**背景**：ADR-005 那次误解造出来的 Ball Lightning 用了一套"沿途反复放电"的脉冲机制。
项目主人明确要求删掉。

**决定**：整套删除 —— `with_pulse` / `is_pulsing` / `PULSE_RATE` / `collides_with_enemies` /
`pulse_ticks` / `pulse_dps` / `max_pulses` / `Projectile._do_pulse` / 电场圈的画法 / 闪电球贴图。

**顺带删了**「增大范围」辅助宝石 —— 它唯一的作用是放大脉冲半径，
脉冲没了它就是一颗"装上去什么都不会变"的宝石，留着比删掉更误导人。

**后果**：`AREA_OF_EFFECT` 属性保留（以后做真正的范围技能还要用），但目前无人使用。

## ADR-012 词缀分四层，装备和辅助宝石那两层「整层重建」

**背景**：装备、辅助宝石、天赋的生效范围完全不同，混在一个 `StatSet` 里没法维护。

**决定**：`CombatEntity` 持有四层，查询时叠在一起算一次四段式：

| 层 | 内容 | 维护方式 |
|---|---|---|
| `gear_mods` | 天赋 / 被动树 | 不变 |
| `equip_mods` | 背包里的装备 | `Player.rebuild()` **整层重建** |
| `skill_mods` | 箭头连着当前技能的辅助宝石 | `Player.rebuild()` **整层重建** |
| Buff | 增益 / 减益 | `BuffContainer` 计时 |

**后果**：
- ✅ 背包一变就整层清空重填，不用追"哪一条该删"，也不会串味
  （箭头指着电球术的「多重投射」不会让火球术也变多发）
- ✅ 顺带修掉一个老问题：以前 `make_player()` 里硬写着 source 叫 `staff` / `ring_of_flame` 的词缀，
  但游戏里根本没这两件东西。现在它们是真装备，**id 保持不变**，所以角色总加成一点没变
  （老的伤害测试全部原样通过），但终于有实物了

## ADR-013 施放时间是「秒」，不是「倍率」

**背景**：`SkillSpec.cast_time` 原来注释成"耗时倍率"，含义模糊。

**决定**：它就是 PoE 技能石上印的**基础施放时间（秒）**。

```
每秒出手次数 = 施法速度倍率 ÷ 施放时间
```

**后果**：「提高施法速度」是缩短这个时间，不是改这个字段本身。
`Player._try_cast()` 里 `_cast_cd = skill.cast_time / speed`。

## ADR-014 不写恒真的断言

**背景**：曾经写过一条断言"SubViewport 鼠标 = 主视口鼠标 − 容器左上角"，
实测发现引擎是**按容器位置实时推算**的，这条永远成立。

**决定**：删掉，只留"值确实变了"这条有效的。

**后果**：写断言之前先问自己 —— **它可能红吗？**
恒真的断言比没有更糟，它给假信心。同理，探针脚本自己也要加断言
（曾经因为探针脚本没检查 `place()` 的返回值，把"脚本选错落点"误判成"存档功能坏了"）。

## ADR-015 文档拆成「给人看的」和「给 AI 看的」，但规约只有一份

**背景**：需要支持多人 + 多 AI 协作，同步到 GitHub。

**决定**：
- `AGENTS.md` —— **唯一的 AI 规约**，Cursor / Copilot / Codex 等通用
- `CLAUDE.md` —— 只是个指针，指向 `AGENTS.md`（Claude Code 会自动读它）
- `CONTRIBUTING.md` —— 人类的流程（环境、分支、提交、PR）
- `docs/` —— ARCHITECTURE（怎么组织的）/ DECISIONS（为什么）/ TASKS（在做什么）

**后果**：规约只有一份，不会出现"各家 AI 遵守不同规则"。
加新的 AI 工具时，只要让它读 `AGENTS.md` 就行。

## ADR-016 局内流程放在独立的 `run/` 层，规矩和 `combat/` 相同

**背景**：加入杀戮尖塔式的局结构（7 步地图 → 战斗/商店 → 奖励三选一 → 最终 Boss）。
流程规则（能不能进房、金币够不够、走到第几步）和战斗数值一样容易出细碎 bug，必须能单测。

**决定**：
- 新建 `run/` 目录（`run_map` / `run_state` / `run_rewards`），**零 Godot 场景依赖**，规矩同 `combat/`
- 依赖方向扩成：`game/` → `data/` → `run/` → `combat/`。
  `run/` 不认识图鉴 —— 奖励候选池由调用方传进来，单测时传假对象就能验规则
- ★ 整局由一个种子决定 ★（地图、奖励候选、商店货架全部从种子推出来）。
  存档只存 `种子 + 步数 + 金币 + 背包`，图和货架读档后**重新生成**，天然一致，
  顺便封死"读档刷奖励 / 刷货架"
- 局模式和沙盒模式用 `RunSession.enabled` 切换：局模式开局只有一颗孤石，
  **不走** GemSave（它会把图鉴缺的自动补进背包，和"一切靠打"直接冲突），
  局的背包存进独立的 `run.json`
- 读档一律回到**当前步的选房阶段**：打到一半退游戏 = 这一步重打，简单无歧义

**后果**：局流程 47 条断言进了 `run_tests.gd`；冒烟测试加了第八段
（孤石开局 → 选房 → 清房 → 三选一 → 回地图）。怪物按步数成长、Boss 都只是
"叠了词缀 / 改了基础值的 CombatEntity"，没有为局模式写任何新战斗逻辑。

## ADR-017 图标是 UI 层的 id 映射；冰缓挂移动速度；怪的追击速度入属性系统

**背景**：接入 `assets/icons/` 下的 19 张图标，并把主动技能从 2 颗扩到 5 颗
（电弧 / 寒冰弹 / 冰霜脉冲）+ 冰霜增强辅助。冰系技能需要一个「冰缓」异常状态。

**决定**：
- ★ 图标按 id 找（`assets/icons/<id>.webp`），映射写在 `UIHelper.gem_icon()` ★
  —— 和格子颜色一样是 UI 层的事，`combat/` 和 `data/` 里**不放任何资源路径**。
  加一件新内容只要丢一张同名图进目录；没有图就退回文字短名，不会变成无名色块
- 图标文件统一用 **.webp 真实扩展名**。曾经 19 张图全是 WebP 却顶着 .png 的
  扩展名，Godot 按扩展名选导入器 → 全部导入失败，这就是"图生成了却没接上"的原因。
  冒烟测试现在会逐件检查图标能否真的加载
- 冰缓（chill）挂在**移动速度 -30%** 上，REFRESH 不叠层。不挂攻击速度 ——
  普通怪从没设过 ATTACK_SPEED 基础值（是 0），挂攻速就是一条恒真数据
- 为了让冰缓真的生效，Enemy 的追击速度从写死的 `CHASE_SPEED` 常量改成
  `stats.get_stat(MOVE_SPEED, 0, CHASE_SPEED)` —— 基础值不变，没有词缀时
  行为和原来一模一样，但 Debuff 从此能减速怪
- 三颗新技能各占一条构筑路，不和老技能重叠：
  电弧 = 弹射专精（怪越密越强）；寒冰弹 = 慢速穿透弹幕；
  冰霜脉冲 = 短射程高伤冰锥，**故意不带**【持续时间】标签（射程就是它的代价，
  能被「延长持续」拉长射程它就只是更强的寒冰弹）

**后果**：主动 5 / 辅助 10，全部自动进入局模式的奖励池和商店（`all_actives()` /
`all_supports()` 是唯一入口）。`run_tests.gd` 新增 4 组断言（新技能参数 / 冰缓 /
冰霜增强连接规则 / 价目表），冒烟测试新增图标加载检查。

## ADR-018 同款宝石叠放 = 合成升级，规则住在 GemGrid

**背景**：局模式的奖励和商店会给出重复的宝石，重复的第二颗除了占格子没有任何用处。

**决定**：
- ★ 把手上的宝石叠到一颗**同 id** 的宝石上 = 合成：手上的被吃掉，那颗升 1 级 ★
  没有额外的合成界面 —— 背包乱斗式背包里，"叠放"就是最自然的合成手势
- 结果等级 = **max(两边等级) + 1**，封顶 max_level。取 max 而不是相加：
  吃掉低级的不亏、吃掉同级的稳赚 1 级，但堆一把 1 级宝石**堆不出**满级
- 技能石和辅助宝石都能合；装备不参与（max_level = 1，没有"升级"可言）
- 目标满级时拒绝，且给专门的原因（"已经满级"），不报"那里已经有东西了"
- 规则实现在 `combat/gem_grid.gd`（merge_target / merge_reject_reason / merge）——
  能不能合和能不能放一样是背包规则，必须能单测；UI 只画金色预览格和发提示

**后果**：`run_tests.gd` 新增 14 条合成断言；冒烟测试用真实点击链路验了一遍
（拿起 → 叠上 → 升级 → 手上的消失）。拖拽预览悬停在同款上显示金色。

## ADR-019 金币不是奖励房型，每清一个战斗房自动进账

**背景**：金币房的问题在实践里很明显 —— 选它 = 这一步构筑不变强，
下一步的怪却照样更硬；它和「实物奖励」放在同一个选择维度上永远是劣势选项。

**决定**：
- ★ 删掉 `RewardKind.GOLD` ★（金币房、金币三选一整个不存在了），
  战斗房外显只剩 4 种：技能宝石 / 装备 / 辅助宝石 / 升级
- 每清一个战斗房**自动**给一笔金币：`RunContent.room_gold(step, rng)`，
  第 1 步 8~14、每往后一步 +3 —— 打到 Boss 前约攒 90~130 金，够逛两个商店
- 数额走 `rng_for("room_gold")` → 同一局同一步定死，读档重打拿到同一笔，刷不了钱
- 金币在**左侧面板常驻显示**（局模式；沙盒没有金币概念所以隐藏），
  战斗画面顶上的状态条保留；清房后的奖励面板顶部显示这一笔进账

**后果**：选房间回归纯粹的"要哪种成长"，金币变成稳定的节奏资源。
`_ensure_guarantees` 的补丁池从「金币或升级」缩成「升级」。

## ADR-020 法杖是技能的载体：宝石镶进法杖，箭头指着法杖

**背景**：项目主人要求"法杖作为技能的载体：每根法杖带一个镶嵌槽位，宝石镶进去，
指着法杖的辅助宝石对槽里的技能宝石生效，玩家初始获得一根法杖"。
这修改了 ADR-006 的"箭头直接指技能石"。

**决定**：
- ★ 技能宝石必须镶进法杖才能施放 ★ 裸放在网格里的技能宝石只是库存
  （不能施放、吃不到辅助、不出现在 Q 的切换列表里）
- `EquipItem` 增加 `socket_count`（法杖 = 1，其它装备 = 0）和 `socketed`
  （槽里那颗 SkillGem）。★ 槽里的宝石不占网格格子 ★ —— 拿起法杖它跟着走，
  存档时作为法杖条目的 `socket` 字段一起存
- 辅助宝石的箭头**指着法杖的任意一格**都算连上，辅助的是槽里的技能。
  法杖 1×2 / 1×3 → 周身 6~8 个箭头位，**法杖越长连线面积越大**，
  换更长的法杖本身就是构筑升级（取代了单格宝石"天然 4 连"的说法）
- 镶嵌手势和合成一致：手上的技能宝石点到法杖上 = 镶入；
  槽里是同款 = 合成升级（同网格叠放规则）；槽里是异款 = 交换（旧的回到手上）。
  取出走详情面板的「取出宝石」按钮（槽里的宝石点不到，必须有专门入口）
- 规则全部住在 `combat/`：`GemGrid.socket_target / socket_reject_reason / socket`、
  `supports_for / arrow_state / link_for / skill_items` 改为以法杖为中心；能单测
- 新装备「见习法杖」1×2：**零词缀**，价值就是那个槽。开局给它（镶着电球术）；
  它也进奖励池/商店 —— 买第二根法杖 = 能多带一个技能。
  ★ 零词缀还有一个工程原因 ★：`make_player()` 会把 `default_loadout()` 的词缀
  全部装上，见习法杖若带词缀，所有基准伤害测试的数值都要跟着改
- 存档版本升到 2（GemSave 和 RunSession 都是）：旧档的裸技能石在新规则下
  放不出技能，直接判旧版重开，不做迁移

**后果**：ADR-006 的"别加回 socket API"就此作废（有了实体载体，socket 是自然表达）。
`run_tests.gd` 的连线/存档/辅助测试全部改写为法杖语义，新增镶嵌规则一组断言；
冒烟测试用真实点击链路验了镶入 / 取出 / 交换。UI 上法杖中格画槽位圆环，
镶嵌预览是青蓝色（区别于合成金色 / 可放绿色）。

## ADR-021 一局 4 层，每层难度递增；金币每关都掉

**背景**：项目主人要求"游戏总共分 4 层，每层难度递增；金币改为每个关卡都掉落，
不存在专门的金币关卡"（后半句 ADR-019 已实现，这里把 Boss 关也补上）。

**决定**：
- `RunMap.FLOORS = 4`。★ 一层 = 一张 7 步的图 ★（复用原来的整套生成规则），
  每层第 7 步是这一层的守关 Boss；第 4 层的才是最终 Boss「骸骨领主」
- 层的流转在 `RunState`：守关 Boss 打赢 → 照常进 REWARD 领三选一 →
  `advance()` 时步数归零、层数 +1、按**层种子**重新生成下一层的图。
  层种子 = `hash([局种子, "floor", 层数])`，拿到局种子就能复现整局 4 张图；
  `rng_for` 的哈希也加入层数，否则每层同一步会掷出同一批奖励
- 难度递增全在 `RunContent` 的数值层（不写任何新战斗逻辑）：
  普通怪每深一层 +50% 生命 / +35% 伤害（INCREASED，和步内曲线相加）；
  Boss 模板按最终形态配，低层每差一层 -20% 生命 / -15% 伤害往下调，
  名字逐层升级（骸骨队长 → 男爵 → 将军 → 领主）
- ★ 金币每关都掉 ★：普通战斗房 `room_gold`（每深一层 +8），
  守关 Boss `boss_gold`（25~35 起，每层 +12）—— Boss 也是关卡，不能白打
- 存档加一个 `floor` 字段；缺字段的旧档按第 1 层读，不炸

**后果**：局的长度从 7 步变成 4 × 7 步；守关 Boss 房在地图上外显奖励类型
（和战斗房同款外显）。`run_tests.gd` 新增层流转 / 层种子 / 层数值曲线断言。

## ADR-022 R 键 = 重开一整局，不是重打当前房间

**背景**：局模式有自动存档，`R` 只做 `reload_current_scene()` 的话，
重载后 `prepare()` 会读到存档、续档回到当前步的选房阶段 ——
实际效果是"重打这一步"。项目主人明确要求 R 重开的是**整局**。

**决定**：
- `RunSession.abandon()`：删局存档 + 清内存里的局状态和读档暂存。
  World 的 R 键处理改成"局模式先 `abandon()` 再 reload"——
  重载后找不到存档，必然开全新的一局（新种子、第 1 层第 1 步、金币归零）
- 沙盒模式不变：R 只重载场景（沙盒没有"局"的概念，背包走 GemSave 照常保留）
- 代价：打炸了想"重打这一步"的后路没有了 —— 这是有意的，
  和"读档一律回到本步选房"（ADR-016）不冲突：**退出重进**仍然续档，
  只有**主动按 R** 才算放弃

**后果**：中途手滑按 R 会直接丢掉整局进度，操作提示改成「R 重开一整局」说清楚。
冒烟测试第八段补了"abandon 后 prepare 必须是全新一局"的断言。

## ADR-023 法杖的词缀只对槽里镶着的技能生效

**背景**：ADR-020 让法杖成了技能载体，但它的词缀仍按 ADR-010 的老规矩全局生效 ——
橡木法杖的「更多 30% 法术伤害」会加给**所有**技能，哪怕技能镶在别的法杖里。
项目主人要求：法杖只增幅镶在它槽里的那颗技能宝石。

**决定**：
- ★ 法杖的词缀改走 `skill_mods` 层（和辅助宝石同层、同命）★：
  `GemLink` 增加 `wand` 字段，`link_for()` 把法杖本身也打包进去，
  `GemLink.mods()` = 法杖词缀 + 辅助词缀 → `Player.rebuild()` 整层塞进 skill_mods。
  Q 切法杖时整层重建，词缀自动跟着"当前用的是哪根法杖"走
- `GemGrid.equip_mods()` 跳过法杖 —— equip 层只剩普通装备（头盔/靴子/戒指照旧全局）
- 空槽的法杖词缀没有作用对象：equip 层不进、link 是空的 → 哪层都不生效
- ★ `DemoContent.make_player()` 的基准口径不变 ★：它仍把橡木法杖的词缀放进
  equip_mods，等价于"正在用橡木法杖里的技能"的总加成 —— 全部老伤害断言原样成立。
  代价是拿它算"别根法杖里的技能"会比游戏内偏高，注释里写明了

**后果**：法杖从"又占格子又给全局加成"变成纯粹的**技能插槽 + 专属增幅**：
换法杖 = 换这个技能的增幅包，装备栏位的取舍更清晰。
`run_tests.gd` 新增作用域断言（equip 层无法杖 / 切法杖词缀跟着换 / 空杖零贡献）。

## ADR-024 等级改成 1~5；辅助宝石没有等级

**背景**：项目主人要求等级不照搬 PoE：技能宝石 1~5 级、辅助宝石干脆没有等级。
一局就 4 层、升级机会有限，1~20 的细密曲线在这个体量里每级毫无手感。

**决定**：
- ★ 技能宝石 `max_level = 5`，每级成长放大到 ≈PoE 的 4~5 级 ★
  （电球术每级 +28 点伤 / +4 消耗，5 级 ≈ 老曲线 20 级的数值；其余四颗同比）。
  合成（叠放/镶入同款）和升级奖励仍是一次 +1 级，规则不动
- 局开局宝石从 3 级降到 2 级（上限变小了，得留出升级空间；2 级 83 点伤够开荒）
- ★ 辅助宝石没有等级 ★：删掉 `mod_growth`，词缀数值 = 模板数值。
  `level / max_level = 1` 两个字段保留 —— 和 EquipItem 一个思路，
  让合成、升级奖励、`[-]/[+]`、存档 clamp 全都**自动**跳过它，不用到处写 if
- 重复的辅助宝石不再能合成 —— 它们的用处是给另一根法杖配同款连线
- 面板/手上提示对 `max_level <= 1` 的东西不显示等级；合成拒绝原因也不再对
  辅助宝石说"已经满级"（走普通的"那里已经有东西了"）
- 旧存档不清档：`clamp_level` 把超界等级自动夹回（15 级电球读回来是 5 级）

**后果**：`run_tests.gd` 加了一条防回退断言 —— 每颗主动技能石的每级成长
必须 ≥ 1 级点伤的 40%，防止有人把成长值改小回 PoE 曲线（5 级封顶配小成长
= 升级没手感）。顺带：新增两件回蓝装备（秘法腰带 3×1、蓝玉护符 1×1），
魔力回复从 Player 的硬常量改走属性系统（`S.MANA_REGEN`，基础 12/秒，
装备词缀在其上按四段式加成）；窗口从 1260×720 提到 1400×800
（内容 700×400 的整数 2 倍，像素均匀、文字按窗口分辨率渲染）。

## ADR-025 丢弃 = 拿在手上 + 两段确认的按钮

**背景**：背包 8×7 就 56 格，奖励和商店会一直塞东西进来，没有丢弃就只能"放弃奖励"。
但销毁是**不可逆**操作，误触把 5 级主力宝石丢了是不可原谅的。

**决定**：
- 手势：把东西拿在手上（左键点它）→ 点「丢弃」按钮**两次** ——
  第一次只发警告并记住"要丢的是哪一件"，第二次点**同一件**才真的销毁
- 任何点击（放下 / 拿起 / 右键）都会清掉确认状态：改了主意就要重新确认
- 丢一根槽里还镶着宝石的法杖，确认提示会写明"槽里的 XX 会一起丢掉"——
  不禁止（两段确认已是足够的保护），但必须说清代价
- 实现全在 UI 层（InventoryUI）：手上的东西本来就不在网格里，
  放掉引用即销毁，`rebuild()` 顺手把"没有它"的背包存盘。`combat/` 零改动

**后果**：什么都能丢（装备 / 宝石都行），丢掉唯一的法杖会让这局打不下去 ——
这是玩家自己的选择，按 R 重开就是。冒烟测试覆盖了两段确认和"改主意"路径。

## ADR-026 触媒：条件触发的特殊辅助宝石

**背景**：项目主人要求"触媒"——特殊辅助宝石，条件达成时自动触发连接的技能：
无施法动作、正常扣蓝、蓝不够不触发。条件：施加感电 3 次 / 点燃 3 次 /
冰冻 1 次 / 击中 5 次 / 移动 20 格 / 每 5 秒。

**决定**：
- `CatalystGem extends SupportGem`（combat/，纯逻辑）：住网格、带箭头、
  连线规则和普通辅助完全一样；不给词缀（mods 空），但魔力倍率照算。
  计数规则（advance / ready_to_fire / consume）全在这个类里，能单测
- ★ 进度封顶在门槛上 ★ —— 蓝不够时不许攒成多次触发，回一口蓝连环爆发就不是"节奏"了
- ★ 触发的是"箭头指着的那根法杖"，不限于当前法杖 ★ —— 触媒的意义就是
  副法杖挂条件自动打，主手照常手动。触发时 Player 临时把 skill_mods 换成
  目标法杖那套算投射物参数，算完换回（命中时用当时的当前词缀 —— 和手动切
  技能同一个已知误差）
- 事件流：击中 = Enemy.damaged（kind != "dot"）；施加异常 = Projectile 施加
  Debuff 时发 `behaviour("buff_<id>")`，World 转成触媒事件；移动 / 计时由
  Player 自己产。触发尝试统一在每物理帧的 `_pump_catalysts()` —— 蓝回来自动补
- ★「冰冻」按冰缓计 ★ 本项目冰系异常是冰缓（ADR-017），没有冰冻状态；
  门槛 1 次所以魔力倍率配最贵（×1.35）。「格」= 一块 16px 地砖，20 格 = 320px
- 6 颗触媒进 `all_supports()`（辅助池 10 → 16），随奖励/商店自然掉落

**后果**：`run_tests.gd` 新增计数/门槛/连线断言；冒烟测试走真实链路验了
"攒 5 次击中 → 触发扣蓝 → 蓝不够不触发 → 回蓝补触发"，并断言点燃事件
真的从投射物上报到了 behaviour_counts。触媒在 UI 里是紫色格子。

**补充（结算口径，项目主人拍板）**：★ 满足施加条件就计一次施加 ★ ——
判定点在投射物命中并通过几率判定的那一刻，和目标身上的状态**无关**：
同一目标重复施加（REFRESH 只续时间）、感电已叠满 3 层，都照样各计 1 次。
"3 次攻击同一目标、每次都够条件 = 3 次感电"。冒烟测试有专门的回归断言
（叠满层的目标再挨 2 发 → 事件 +2）。顺带修了"看不见计数在走"的问题：
触媒格子底部画实时进度条，详情面板停在触媒上时进度文本每 0.2 秒刷新。

**补充 2（防循环，项目主人拍板）**：★ 触媒触发出来的技能不能喂触媒 ★ ——
触发产物的击中 / 施加异常一律不给**任何**触媒攒进度（不只是触发它的那颗：
两颗触媒也能互相接龙成环，所以一刀切）。实现：`ProjectileState.from_trigger`
标记（纯逻辑，分叉出来的子弹继承），投射物上报施加事件、World 数击中时都看它。
移动 / 计时不受影响 —— 那是玩家行为，不是技能产物。等同 PoE 的
"被触发的技能不能再触发"。异常本身照常施加到目标身上，只是不计数。

## ADR-027 调试控制台：往背包里生成任意物品

**背景**：调数值 / 试构筑每次都要真打或者改代码铺背包，太慢。
项目主人要求一个能生成物品、带类型筛选的 GUI 控制台。

**决定**：
- `game/console_ui.gd`，按 ` 或 F1 开关，盖在右侧战斗画面上（开着时挡住
  点击防误施法；左侧背包面板照常可用，生成完立刻能摆）
- 筛选五档：全部 / 技能宝石 / 辅助宝石（不含触媒）/ 触媒 / 装备 ——
  按**类型**过滤（`is SkillGem` 等），加新内容不用改控制台
- 点一件 = `GemSave.resolve` 一颗**新实例** `place_anywhere` 进背包；
  放不下就提示，不硬塞。走 `player.rebuild()` 顺手存盘
- ★ 它是作弊面板，紫色描边标明身份 ★ 不做防沉迷：单机游戏，主人说了算

**后果**：set_open / set_filter / filtered_things / spawn 拆成公开方法，
冒烟测试不用模拟鼠标就能验开关、五档数量、生成落袋。
